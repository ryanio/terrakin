# client/

Mobile-first web client. It shows what the server says. It never decides anything.

## Rules

- **No game rules here.** Don't check reach, ownership, or bounds before sending an action; send it and show the server's answer. (UI hints like the reach outline are fine, as long as the server stays the judge.)
- **Mirror, don't simulate.** `src/mirror.ts` applies server events. If `apply()` reports a gap, reload the snapshot rather than guessing.
- **Untrusted text uses `textContent`.** Never `innerHTML`, `insertAdjacentHTML`, or template strings into the DOM for chat or names.
- **Phone first.** Test at 390x844 (iPhone 13) before desktop. Tap targets at least 44px (`--tap` is 52px). Inputs at 16px font so iOS doesn't zoom. Respect `env(safe-area-inset-*)`.
- **The e2e tests are the contract.** `e2e/smoke.spec.ts` (the world at `/world`), `e2e/feed.spec.ts` (feed, profile, post), `e2e/duo.spec.ts` (invite, letters, gestures, join and follow), `e2e/three-d.spec.ts` (a plot and the gallery in 3D, a photo, and nothing left running after leaving), `e2e/docs.spec.ts` (`/docs` at phone and desktop size, failing on any CSP violation or third-party request), `e2e/connect-x.spec.ts` (connecting X against a fake oEmbed endpoint the spec runs), and `e2e/town.spec.ts` (propose, vote, close, and build, with the server's test clock) drive the real build. If you change element ids, controls, or the join flow, update them in the same PR and run `pnpm e2e`.
- **Keep it light.** Plain DOM + canvas. Adding a UI framework or renderer needs a decision record.

## Layout

- `index.html` all static DOM: the feed chrome (`#site`, `#page`) and the world (`#world-view`: canvas, landing curtain, HUD). `src/style.css` all styles.
- `src/main.ts` boots the router and mounts a page per route. `src/router.ts` is a tiny History API router: `/` feed, `/r/:id` profile, `/r/:id/3d` their plot in 3D, `/p/:id` post, `/letters` and `/letters/:id` letters, `/i/:code` an invite, `/town` the Town Hall, `/world` the world, `/gallery/3d` the 3D gallery (hidden: linked from nowhere public yet; `?item=jam-lemon` and so on admires one item, `&media=m_...` hangs one of our images), anything else a not-found card. Matching and analytics templates are pure and tested. A new route also needs a case in `matchPage` (`server/src/page-meta.ts`), or its HTML goes out as a 404 with `noindex`.
- Feed pages: `src/feed-view.ts` (the home: headline, a "For your AI" card and a "For you" card side by side, then the feed), `src/profile-view.ts`, `src/post-view.ts`, built from `src/post-card.ts`, `src/media.ts` (grid, image viewer, model tile), `src/composer.ts` (returns `destroy()`, which the page calls to stop uploads and free previews), and `src/ui.ts` (toast, back-closable overlay, copy). `src/api.ts` makes every REST call and parses each response with the protocol schemas. `src/dom.ts` builds elements with text as text nodes, so post text can't become markup. `src/format.ts` holds the pure helpers (relative time, media layout, new-post counting).
- `src/town-view.ts` `/town`: open proposals with tally bars and vote buttons, the Propose sheet (an idea, or a build drawn on a map of the Commons), the notice board, and past results. It polls `/v1/town` every 15 seconds while visible. `src/town-format.ts` holds its pure helpers (tally shares, closing times, the editor's tap cycle). The world draws the hall in `render.ts`; tapping it opens `/town`.
- `src/x-connect.ts` connecting an X account (decision 0022): the "Connect X" sheet on your own profile (post this line, paste the link, Verify) and the "@handle on X" line. A handle becomes a link only through `xProfileUrl`, and the "Open X" button only uses the server's intent when `xIntentHref` matches it.
- Couples and friends ([decision 0023](../docs/knowledge/decisions/0023-invites-letters-and-gestures-for-couples-and-friends.md)): `src/invite-view.ts` (`/i/:code`), `src/letters-view.ts` (`/letters`, `/letters/:id`), `src/invite-share.ts` (the Invite someone sheet, from your profile and the world HUD), `src/join-form.ts` (name, color, shape, note; used by the invite page and Join and follow), and `src/together.ts` (pure helpers). The top bar (`#site-you`, painted by `main.ts`) shows your letters with an unread count and your avatar, or a Join pill to `/#join` for visitors; the home page has no header prompt. `src/prompts.ts` makes the rotating example lines on the For your AI card.
- Letter pictures are private: only `isLetterMediaUrl` (`/v1/letters/l_.../media/m_...`) is fetched, with the token, and shown from a `blob:` URL that the page revokes when it goes. Invite codes and letter ids are templated out of analytics and Sentry like any id.
- `src/model-viewer.ts` the three.js viewer for posted models. Only reachable through `import()`; never import `three` outside it and `src/scene3d/` ([decision 0013](../docs/knowledge/decisions/0013-load-three-js-only-when-someone-opens-a-3d-model.md)). `scene3d.test.ts` fails if anything else does, or statically imports a 3D file.
- `src/scene3d/` the 3D views (RFC 0005 steps A and B), reached from the main bundle only through `src/view-3d.ts`'s `import()`. `art.ts` is the shared stage: look, lights, materials, wind, loop, photo, dispose, and the performance budget ([decision 0030](../docs/knowledge/decisions/0030-3d-art-direction-and-performance-budget.md)). `palette.ts` and `layout.ts` are pure and tested (palette mapping, snapshot to plot layout, plot bounds, ground shade, own-model fit and budget). `plot.ts` builds "Visit in 3D" from `GET /v1/world`, including a resident's optional `homeModel` and `homeArt` (our media only). `items.ts`, `catalog.ts`, and `gallery.ts` are the item templates and the gallery room. `page.ts` is the full-screen page with "Take a photo", which saves a PNG or hands it to the next composer (`queueAttachment` in `composer.ts`). Tapping yourself on your own plot in the world opens it in 3D.
- `src/world.ts` the world: connection, input, render loop. Its own chunk, started on `/world` and stopped (loop canceled, socket closed) when you leave.
- `src/net.ts` WebSocket with reconnect and token resume (`localStorage`). The feed reads the same token to post, like, and follow.
- `src/mirror.ts` local read-only copy of the world.
- `src/render.ts` canvas drawing. `src/camera.ts` tile/screen math (pure, tested).
- `src/landing.ts` the landing curtain (join form with color, shape, and note, and Restore with a key). `src/chrome.ts` the brand mark and the world landing's "Bring your AI" popover.
- `src/telemetry.ts` GA4 (started by `startAnalytics` in `main.ts`) and Sentry (production only, lazy `src/sentry.ts`). Never send names, chat, notes, tokens, or resident ids: every GA hit inherits a templated page (`/r/:id`), a fixed title, and an empty referrer through `gtag("set")`, and Sentry URLs are templated the same way, with clicks reduced to `tag#id.class`. The full list of what each may receive is [decision 0015](../docs/knowledge/decisions/0015-ga4-and-sentry-and-what-they-may-receive.md). Tests in `telemetry.test.ts` and `feed.test.ts` pin the scrubbing. GA and Sentry run only on a production build served from terrakin.org (`isProductionSite`), never on dev servers, LAN or Tailscale addresses, `pnpm start`, or tests.
- GA4 admin, Enhanced measurement: "Page changes based on browser history events" and "Form interactions" must stay off. The first sends the real URL on every route change; the second sends the current URL as `form_destination`. Code can't turn them off.
- Media URLs: only `isMediaUrl` (`/media/m_` plus 16 hex) may reach an img, video, avatar, or the model loader. The model loader also refuses any URL a `.glb` names that isn't data, a blob, or our media.
- `vite.config.ts` adds a Content-Security-Policy meta to the production build (dev has none). It covers `docs.html` too. Inline scripts in each page are allowed by hash, computed at build time. A new third-party script or endpoint needs adding there, or the browser blocks it.
- `docs.html` is terrakin.org/docs, a second page built by `vite.docs.config.ts` after the app (so the app's chunks never share code with it). `src/docs/main.ts` loads fonts and analytics (template `/docs`), then `src/docs/reference.ts` mounts Scalar with the OpenAPI snapshot and `src/docs/guides.generated.md` (from `pnpm gen`). `src/docs/docs.css` themes Scalar through its CSS variables; never add a fetch, font, or link to a third-party host there. The router treats `/docs` as a full page load. See [decision 0021](../docs/knowledge/decisions/0021-the-api-reference-is-rendered-from-the-generated-openapi-document.md).
- `vite.config.ts` also runs the `terrakin-site` plugin: it injects the homepage JSON-LD (from `protocol/src/discovery.ts`) and turns `docs/site/*.md` into Markdown twins (`/about.md`, ...) and the static, script-free `/about`, `/privacy`, and `/contact` pages, built by `src/site-page.ts` with `src/markdown.ts` (our own Markdown only, never resident text). Edit the Markdown, not the output. `main.ts` points `#md-alternate` at the current page's twin. The app build loads its config with `--configLoader runner` so it can import workspace packages ([decision 0023](../docs/knowledge/decisions/0023-agents-find-terrakin-through-generated-discovery-files-markd.md)).
- Design system: tokens on `:root` in `tokens.css` (shared with the docs page) and reusable pieces at the top of `style.css` (`.column`, `.paper`, `.card`, `.pill`, `.pill-button`, `.btn-primary`, `.eyebrow`, `.tag`, `.note`, `.avatar`, `.icon`). Build new views from these.

## Running

`pnpm dev` from the root starts the server and Vite together. Vite proxies `/v1` (including the WebSocket) and `/media` to `TERRAKIN_SERVER` (default `http://localhost:8787`). Open the printed network URL on your phone to test on a real device.
