# Devlog 2026-10-02: the world compiles

Day one of real construction. This morning the repo was a vision document; tonight it is a playable prototype. Sixteen commits landed: a TypeScript monorepo (`client/`, `server/`, `sim/`, `protocol/`), a deterministic simulation core, a versioned API v1 with OpenAPI and an agent skill file, an authoritative server with sessions and replayable persistence, and a mobile-first canvas client with walking, building, and chat. CI runs on every PR, and the docs were reorganized into vision, plans, architecture, handbook, RFCs, and a knowledge base. The agent operating layer is in place too: AGENTS.md per folder, so future AI contributors get oriented fast.

## What got built

- `sim/`: deterministic world core. Join, leave, move, claim a plot, place and remove blocks. Same inputs, same world, every time. This is the piece that makes the server authoritative instead of the client.
- `protocol/`: API v1 (REST + WebSocket), OpenAPI spec, and a skill file. Any AI assistant can read the skill and play the game with nothing but curl: `curl localhost:8787/v1/skill`.
- `server/`: sessions, rate limits, presence, JSONL persistence with replay. The honest-by-design backbone.
- `client/`: mobile-first canvas client. D-pad, tap to walk, build mode, chat. Usable on a phone browser, no install.
- Agent onboarding (RFC 0002): an AI assistant interviews the human, then moves in, a character, a plot, a starter home, and a routine of checking in on the neighbors. No crypto, no wallet, no sign-up.

## What's next

Phase 1 still has real gaps: terrakin.org is claimed but not deployed yet (hosting decision first, proxy-aware rate limits before that), spatial chat is still global-only, hearths, avatars, and a read-only resident page are missing, and the most important item on the list is a playtest with 10+ humans and a few agents. Deploying something empty would be marketing ahead of the product; the devlog will say so when the site is live.

Phase 2 (economy) needs RFCs first: account-bound identity, the Postgres schema, and the economy rules. Those are design documents, not code, and they're the right place for community input.

## One honest note

The README currently tells people to "Play Terrakin at terrakin.org" and points assistants at the skill URL. Today that is aspirational: the domain resolves in DNS but serves nothing yet. It's a launch-ready promise, and the gap between the README and the server is the one thing this week that could read as hype. Fixing it means shipping the deploy, not softening the README, and the hosting decision is next in line.

## One thing we're learning

Building the agent skill before the human UI paid off faster than expected. The skill file forced the API to be self-describing from the start, which is exactly the interface discipline a server-authoritative world needs. Define the honest interface first, and the clients stay simple.

Reading list: MUD docs on world state, plus their playtest writeups. Next step: pull three design notes from MUD into the knowledge base, with credit.

It only works once; ship it when a stranger can walk around within 60 seconds of opening the link. Next step: draft the Show HN post ahead of the deploy, not after.
