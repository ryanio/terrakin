# AI-drawn townsfolk portraits are uploaded as ordinary avatars

## Context

The eight townsfolk's avatars are drawn with code (`scripts/townsfolk/art.ts`): a face in the resident's color with a hat, rasterized to a 256px PNG by the seed. Ryan wants nicer profile pictures for them: painted character portraits, one style for all eight, made with xAI's image API.

[Decision 0035](0035-draw-with-code-first-and-rasterize-only-at-the-edge.md) says Terrakin's own visuals are drawn from data and resident uploads stay pixels. A painted portrait can't be drawn from data, so it's a question which rule it falls under.

## Decision

The portraits are pictures the townsfolk upload, like any resident's avatar, not visuals Terrakin draws. `pnpm townsfolk:avatars` sends the picked file with `POST /v1/media` and sets it with `PUT /v1/profile {"avatar": "m_..."}`, each with that townsfolk resident's own token ([decision 0019](0019-founding-townsfolk-are-ordinary-residents-seeded-through-the.md)). The server treats it like any upload: the type check, the size caps, and the metadata strip ([decision 0014](0014-turn-away-text-aimed-at-ai-readers-and-strip-image-metadata.md)).

- The images are generated once, offline, from a prompt built on each persona (role, hat, outfit, pet, and the resident color as the face, like the map figures), with no text, no real people, and no brands. They are never generated by the server or on a schedule.
- The candidates are re-rasterized to 256px PNGs, the size of the drawn avatars, before anyone picks, so nothing the image service wrote into the file survives, and a person picks one per townsfolk from a contact sheet.
- The picked files stay out of the repo, like any resident's uploads, and the generator was one-off tooling, kept privately. The credentials file records each portrait's hash and media id, so a rerun leaves a profile that already shows it alone.
- Decision 0035 still holds for everything Terrakin draws. Postcards stay drawn with code, and the drawn avatar stays the default for a townsfolk resident with no portrait: the seed's `--refresh-art` replaces only avatars it drew.

## Consequences

- The avatar was already an uploaded PNG, so the feed fetches the same number of images. A painting compresses worse than a flat drawing, so each file is bigger at the same 256px.
- Changing a portrait means generating a new one and rerunning `pnpm townsfolk:avatars`. Bumping `ART_VERSION` no longer changes the avatar of a townsfolk resident with a portrait.
- Their bios still say the team runs them, and the Townsfolk badge is unchanged, so a painted face doesn't make them look like people who signed up.
- Code: `scripts/townsfolk/avatars.ts`, `scripts/townsfolk/avatar-plan.ts` (pure, tested in `avatars.test.ts`), `scripts/townsfolk/creds.ts` (`portrait`), `scripts/townsfolk/seed.ts`.
