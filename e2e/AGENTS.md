# e2e/

Playwright tests that drive the real production build on an iPhone 13 viewport. They are the contract for the client: if you change element ids, controls, or a flow they cover, update the spec in the same commit and run `pnpm e2e`.

## Rules

- **E2e owns flows only it can see.** A test here walks a person through the real UI against the real server: a flow that crosses client and server, the live socket, sign-in and keys, uploads, the staff app, and the 3D views loading. An API rule, a refusal, a count, copy, or an edge case belongs in the `server`, `sim`, `protocol`, or `client` tests, which are faster and say what broke; check there before adding it here. Grow an existing test with a `test.step` rather than adding a test that repeats its setup (join, sign in, settle, move the clock), and keep about one test per flow.
- **Real servers, one IP.** `playwright.config.ts` builds the client and starts the Node server on :8790 (through `servers.ts`) with test-only settings: a higher join limit (`TERRAKIN_SESSIONS_PER_MINUTE`), a movable clock that starts in the world's morning, so pictures of the world don't depend on the hour (`TERRAKIN_TEST_CLOCK`), a way to name a maintainer, a fake X oEmbed endpoint (`TERRAKIN_TEST_X_OEMBED`), a fake network and card host for agent links (`TERRAKIN_TEST_CHAIN`), and the town's own events off the calendar (`TERRAKIN_TOWN_EVENTS=off`), so a moved clock never lands in the harvest night. Most specs share that server, so don't assume an empty world. A suite uses ten ports from `TERRAKIN_E2E_PORT` (`ports.ts`), so set it ten or more apart to run two suites at once from different worktrees.
- **Never settle a fixed plot.** Specs share one world and run side by side, so a plot one spec counts on can be taken by another. Settle with `settleFree` (or `settler`) on plots from `freePlots`, which tries the next when one is taken.
- **Shared helpers live in `support.ts`** (`join`, `act`, `read`, `signIn`, `freePlots`, `settleFree`, `settler`, `advanceDay`, `advanceMinutes`, `sweep`, `tapTile`, `watchErrors`, `overflowsSideways`, `touchingCards`, `tinyPng`, `countFrames`, `framesWhileIdle`). `sweep` runs the server's minute sweep now (`POST /v1/test/sweep`), which only does what the next minute would, so a spec that uses it shares the main server. Every spec uses them. When a spec needs a variant (an agent, a color, a retried join, dialogs failing the test), add an option to the helper rather than a copy; `packages/client/src/e2e-support.test.ts` fails on a spec that defines its own.
- **Specs that move the clock get their own server.** `town`, `coins`, `praise`, `make`, `shop`, `market` and `bounties` move the clock a day or more on, which would expire what other specs hold. Each is listed in `CLOCK_SPECS` in `ports.ts`, has its own Playwright project pointed at its own server, and runs beside everything else. `servers.ts` builds the client and starts every server: the clock specs' while the build runs, and the main server last, once the build is done and the others answer, so Playwright waits on that one. A new spec that calls `advanceDay` joins that list.
- **A test has 30 seconds on a laptop and 60 on CI** ([decision 0109](../docs/knowledge/decisions/0109-ci-gives-each-e2e-test-60-seconds-and-a-laptop-still-30.md)). One that needs more than 30 locally is too slow: split it into serial tests that share what the first one sets up, as `three-d.spec.ts`, `shop.spec.ts`, and `town.spec.ts` do, rather than raising its timeout.
- **`three-d.spec.ts` and `world-3d.spec.ts` run after the rest, one at a time.** Software WebGL draws every frame on the CPU, and next to other specs a small CI runner queues their taps past the timeout. CI runs each in a job of its own (`TERRAKIN_E2E_ONLY=3d` with `--project`, and `--no-deps` for `world-3d`) beside three shards of the 2D specs (`TERRAKIN_E2E_ONLY=2d`); see `.github/workflows/ci.yml`. A new spec that opens a 3D view joins that chain.
- **Fail on what users would hit.** Page errors and Content-Security-Policy refusals fail a test; `docs.spec.ts` also fails on any request to another host.
- **No outside network.** Seed data over the local REST API; `connect-x.spec.ts` runs its own fake X, and `partners.spec.ts` its own fake network.
