# packages/client/

Mobile-first web client. It shows what the server says and never decides anything. How the pages fit together: [docs/architecture.md](../../docs/architecture.md).

## Rules

- **No game rules.** The server decides; show its answer, in plain words (`worldProblem` in `src/things.ts` for the world's refusals). You may hold back a button the mirror or your inventory already shows it would refuse (no plot for Build, an unripe crop), as long as the reason is on screen and the check is the sim's own exported function (`canBuildOn`, `isReady`, `harvestFits`), never a copy ([decision 0052](../../docs/knowledge/decisions/0052-the-client-holds-back-actions-the-sim-would-refuse-using-the.md)). UI hints like the reach outline are fine. A cost, a name, or a rule a page shows comes from the sim or the server's answer, never a number or a list written here.
- **Mirror, don't simulate.** `src/mirror.ts` applies server events. If `apply()` reports a gap, reload the snapshot.
- **Resident text is text.** Build DOM with `h()` from `@terrakin/ui/dom` or `textContent`. Never `innerHTML`, `insertAdjacentHTML`, or template strings for names, chat, posts, or notes. On a canvas, chat and names are canvas text only. Lines that carry a resident's name use the player-text style.
- **Phone first.** Test at 390x844 before desktop. Tap targets at least 44px (`--tap` is 52px), inputs at 16px so iOS doesn't zoom, respect `env(safe-area-inset-*)`. In the world the map is the point: under 480px the HUD gives back as much of it as it can (decisions [0303](../../docs/knowledge/decisions/0303-on-a-phone-the-world-s-controls-are-icons-round-the-map.md) and [0304](../../docs/knowledge/decisions/0304-the-world-s-chrome-names-itself-and-steps-aside-while-you-wa.md), one media query at the foot of `src/world.css`), so a new control there is weighed against the world it hides. Every button there says what it does in words, the four actions with the word under the icon; only the speaker and the 3D view go by their sign alone. While you walk (`data-walking` on the HUD) the corner chrome dims and comes back when you stop, while what the world pins to your figure or says to you stays bright; it never moves or hides, so a button stays under your thumb and in the accessibility tree. Nothing on a page scrolls sideways.
- **Reduced motion.** Under prefers-reduced-motion everything that moves holds still (signs, weather, fireworks, flames, the kiln reveal), and figures stand on their tiles while walks keep their pace.
- **Only our media.** An img, video, avatar, or model loader takes a URL only through `isMediaUrl` (`/media/m_` plus 16 hex). Letter pictures go through `isLetterMediaUrl` (`src/letter-media.ts`), fetched with the token and shown from a `blob:` URL the page revokes. Partner art only through `isPartnerArt` (`/partners/<id>/<name>.svg`, our own copies in `public/partners/`).
- **The first load has a budget.** The build fails when the entry script and what it imports up front pass `FIRST_LOAD_BUDGET` gzipped (`vite.config.ts`, [decision 0110](../../docs/knowledge/decisions/0110-the-first-page-load-has-a-gzipped-size-budget-the-build-enfo.md)). The budget never buys a smaller number with worse code ([decision 0258](../../docs/knowledge/decisions/0258-the-first-load-s-budget-is-135-kb-counted-as-it-is-downloade.md)): no shorter names, merged functions, or helpers left in the wrong module to save bytes. Run `node scripts/first-load.ts` before and after a change to it. The build cuts the first load into `vendor`, `rules`, and the entry by package ([decision 0259](../../docs/knowledge/decisions/0259-the-first-load-is-three-files-cut-by-package-the-libraries-t.md)), so more modules cost nothing, but a module the first load imports rides in it even when only a lazy page uses it. So:
  - Every page but the feed is built through `lazyView` in `main.ts`'s `pageFor`; a new page goes there as an `import()`.
  - REST calls are one module per API area in `src/api/`, and a page imports its own area's. A call only a lazy page makes never goes in a module the first load imports, and there is no file that re-exports them all. `src/first-load.test.ts` lists the areas the first load may import.
  - A style only a lazy view draws goes in that view's own stylesheet, beside its module and imported by it (`world.css` by `world.ts`); `src/style.css` holds what the first load can show. `src/shared-components.test.ts` fails on a sheet imported anywhere else ([decision 0264](../../docs/knowledge/decisions/0264-a-lazy-view-s-styles-load-with-its-module-and-the-first-load.md)).
  - A helper a first-load module needs lives in a small module of its own, never in a page's module (`letter-media.ts`, `visit-plot.ts`, `world-link.ts`).
  - The build drops the protocol schemas' descriptions (`noSchemaDescriptions`, `src/strip-describe.ts`, [decision 0163](../../docs/knowledge/decisions/0163-the-client-build-drops-the-protocol-schemas-descriptions.md)) and stands in for zod's JSON Schema modules (`noJsonSchema`, `src/no-json-schema.ts`, [decision 0231](../../docs/knowledge/decisions/0231-the-client-build-leaves-out-zod-s-json-schema-code-and-draws.md)).
- **three.js stays lazy.** Import `three` only in `src/model-viewer.ts` and `src/scene3d/`, reached through `import()` ([decision 0013](../../docs/knowledge/decisions/0013-load-three-js-only-when-someone-opens-a-3d-model.md)); `view-3d.ts` and `world.ts` are the only doors into `scene3d/`. `scene3d.test.ts` fails otherwise. 3D work follows the art direction and budget in [decision 0030](../../docs/knowledge/decisions/0030-3d-art-direction-and-performance-budget.md), and the world in 3D the view radius and frame budget in [decision 0060](../../docs/knowledge/decisions/0060-the-world-in-3d-draws-a-view-radius-around-you-within-a-fram.md): no new lights and no shadows for the night ([decision 0098](../../docs/knowledge/decisions/0098-evenings-and-nights-in-3d-follow-the-map-s-clock-with-lamps-.md)).
- **Sound stays lazy, and off until tapped.** The sound code (`src/sound/soundscape.ts`, `voices.ts`, `mix.ts`) is reached only through `import()` from `src/sound/switch.ts`, which makes the AudioContext inside the tap that turns sound on, never before ([decision 0097](../../docs/knowledge/decisions/0097-the-world-s-sound-is-made-with-code-off-until-the-speaker-is.md)). `sound.test.ts` fails on a static import, and `e2e/sound.spec.ts` on a context made before the tap. Sounds are made with code, never files, and only your own moments make one.
- **Telemetry gets templates, not people.** GA4 and Sentry never see names, text, tokens, or ids: pages are templated (`/r/:id`), titles fixed, clicks reduced to `tag#id.class`. They run only on a production build served from terrakin.org, and Sentry only in browsers new enough to run the app, dropping any error whose every script is a browser extension's (`fromBrowserExtension`). What each may receive is [decision 0015](../../docs/knowledge/decisions/0015-ga4-and-sentry-and-what-they-may-receive.md); `telemetry.test.ts` pins it. Our own breadcrumbs go through `appCrumb` and carry codes and templates, never text. In GA4 admin, Enhanced measurement's "Page changes based on browser history events" and "Form interactions" must stay off.
- **The CSP is in `vite.config.ts`.** A new third-party script, font, or endpoint needs adding there, or the browser blocks it. `jitless.ts` is imported first so zod never probes `new Function` and the CSP sees no eval. The docs are static pages and load nothing beyond the site's stylesheet, fonts, and their one script.
- **A new route needs a case in `matchPage`** (`packages/server/src/page-meta.ts`).
- **The e2e suite is the contract.** Changing element ids, controls, or the join flow means updating `e2e/` in the same commit ([e2e/AGENTS.md](../../e2e/AGENTS.md)).
- **Keep it light.** Plain DOM and canvas. A UI framework needs a decision record.
- **Pick a page layout.** Every page is a `pageLayout` (main and sidebar), a `wideLayout` (a grid of cards: Visit, Galleries), or a `.column` (forms and lists). Put what someone came for in the main column and what supports it in the sidebar ([decision 0191](../../docs/knowledge/decisions/0191-every-page-is-a-sidebar-layout-a-wide-card-grid-or-a-column.md)).
- **A page loads through `lazyView` and `pageData`.** `lazyView` shows `skeletonPage` in the page's own layout (`SHAPES` in `main.ts`) until the page's `ready` resolves, with the page in the document but hidden ([decision 0251](../../docs/knowledge/decisions/0251-a-page-loads-behind-placeholders-in-its-own-layout-and-shows.md)). So a page draws no placeholders of its own for its first load, nothing in its `load` may measure, scroll, or take focus before `ready`, and `ready` resolves once the first content is in, not after later requests. A page that has to (a post's reply box, a letter thread, or tabs that open a sibling page) passes `own` and shows its own placeholders. A new page gets its data through `pageData` in `page-data.ts` ([decision 0254](../../docs/knowledge/decisions/0254-a-page-asks-for-its-data-through-one-loader-and-a-refresh-th.md)): it drops answers for a page that was left, never overlaps asks, and a failed refresh leaves the page as it is. The feed, the profile, and the Town Hall keep their own loads.
- **A system shows only once it is open.** Jobs, circles, recipes, levels, pottery, lands, ways, and the plot market draw nothing and ask nothing until the snapshot or a profile says the world has opened them (`jobsOpen`, `circlesOpen`, `recipesOpen`, `level`, `clayOpen`, `plotMarketOpen`, ...). A world without one draws exactly as it did. Every Node world opens the systems terrakin.org runs ([decision 0373](../../docs/knowledge/decisions/0373-every-node-world-opens-the-systems-terrakin-org-runs-recipes.md)).
- **A button sends the server's moves.** Where the server lists `you.moves` (events, bounties, games, circles, jobs), a button is one of them, and a refusal shows in words under it. Anything that spends coins, gives something up for good, or can't be undone is a second tap (`confirmTwice`): Hand in, Add an upstairs, paying or taking back a bounty, buying a plot, taking a plot listing back.
- **Build from the design system.** Tokens are on `:root` in `packages/ui/src/tokens.css`, sizes come from its scales, and layout from the primitives (`stack`, `cluster`, `plain-list`) ([packages/ui/AGENTS.md](../ui/AGENTS.md)); shared pieces are in `packages/ui/src/base.css`, which `src/style.css` imports. The staff app uses the same two files.
- **Use the shared components.** Root rule 11. Avatars, `personLink`, badges, `timeAgo`, state cards, empty notes, checkbox rows, sheets, and paths come from `packages/ui/`, with their styles in `base.css`. Here: `actProblem` (`src/api/world.ts`) for action results, `actFromButton` (`src/act.ts`) for a button that sends one action and refreshes the purse and page, and `colorChips`, `hairColorChips`, `hairChips`, `shapeChips`, and `dotChips` (`src/join-form.ts`). Don't build one by hand or restyle it here; `src/shared-components.test.ts` fails if you do, and on a selector defined twice in `src/style.css`.

## Writing tests

Before adding a unit test here, answer four questions, and hold the test until you can:

1. What behavior does it protect: something a person sees, a contract, or a rule above?
2. What regression makes it fail?
3. Why doesn't an existing test catch that already? Extend a table or a shared fixture instead of adding a near-copy.
4. Does it need an export, flag, or hook that no production code uses? Then test the real caller instead.

Test at the lowest level that catches the bug, as the root `AGENTS.md` says. Here that means the pure functions (words, layouts, the mirror, the walker) given real inputs. A test that copies a constant or a list, restates a lookup table, or checks a value against the function that made it protects nothing. The source checks in `shared-components.test.ts`, `scene3d.test.ts`, `sound.test.ts`, and `first-load.test.ts` stay, because each is the cheapest guard of a rule above. A module this file calls "pure and tested" keeps its decisions out of the DOM code so they can be tested that way.

## Rules by system

Home wall:
- The town comes before the posts, and the wall never leads with an empty number: the pulse card's second number is who's online, else plots claimed, and who's around never lists you ([decisions 0236](../../docs/knowledge/decisions/0236-the-home-wall-shows-the-town-before-the-posts-and-folds-a-lo.md) and [0270](../../docs/knowledge/decisions/0270-the-home-wall-never-leads-with-an-empty-number.md)). A long post folds behind Show more (`foldText`); its pictures always show. Nothing on the wall scrolls in a box of its own.
- The first paint goes in at once: the composer, the cards above the posts, and the posts wait behind one `.wall-fill` placeholder until all are in or `FIRST_PAINT_MS` passes (`whenPainted`). `e2e/feed.spec.ts` holds its layout shift under 0.05. A card that loads after the paint joins only once its place is scrolled out of sight (`whenUnseen`), so it never moves what's being read.
- New posts come as ids on a `watch` socket while the page is visible, with polling as the fallback ([decision 0046](../../docs/knowledge/decisions/0046-new-posts-go-out-as-ids-on-the-live-socket-and-check-ins-ans.md)). Townsfolk fill in only while real activity is thin ([decision 0034](../../docs/knowledge/decisions/0034-townsfolk-fill-the-home-wall-only-while-real-activity-is-thin.md)). The devlog card, once opened or hidden on this device, stays away until a newer post ([decision 0105](../../docs/knowledge/decisions/0105-the-devlog-is-published-like-the-changelog-and-the-check-in-.md)).
- The front page's live line has its height set before any part is in, each part one line cut short, so filling it moves nothing; it shows no 0 and no line for an empty town ([decision 0273](../../docs/knowledge/decisions/0273-the-front-page-shows-visitors-one-live-line-of-the-town-s-co.md), [0374](../../docs/knowledge/decisions/0374-the-front-page-s-live-line-also-names-the-next-event.md), [0375](../../docs/knowledge/decisions/0375-the-front-page-and-pulse-card-count-every-claimed-plot-the-t.md)).

Posts and social:
- Mentions, quotes, and web addresses go into text nodes and links, never HTML, and a link in a post leaves through `/away`, which names the host and shows the whole address.
- A like, reaction, or repost shows at once and goes to the server one request at a time (`PostToggles`), so a quick second tap is never lost and the counts end as the server's.
- A profile's avatar repaints on `MY_PROFILE_EVENT`, fired by `rememberMyProfile` and `forgetMe` after you change your own profile.

Joining and guests:
- Someone with no character walks the town first as a guest ([decision 0380](../../docs/knowledge/decisions/0380-a-newcomer-walks-the-town-as-a-guest-first-and-moves-in-with.md)): a figure put in the mirror as `GUEST_ID`, walked by the same `Walker` and answered here, never sent, never counted, seen by nobody else. A guest's tap only walks. The canvas's `data-at` is where your figure stands, a guest's too. Its `data-settled` says the near column has taken its first shape (`markNearSettled` in `world.ts`), which e2e taps wait for.
- A name field keeps to the naming rule as it's typed (`nameRule`): the sim's `NAME_RULE_WORDS` as the hint and the sim's `nameProblem` asked before anything is sent. Suggest fills the field only while it's empty or still holds the last idea, so a typed name is never overwritten, and never offers a name the server refused with `name_taken`.
- A fresh join settles the plot Live here was tapped on, else opens the Claim plot picker ([decision 0377](../../docs/knowledge/decisions/0377-a-person-who-joins-at-the-door-is-offered-a-plot-straight-aw.md), `claimOnJoin`), never for a returning character or a join from a link's place.
- No shape on join ([decision 0140](../../docs/knowledge/decisions/0140-a-person-joins-with-hair-a-top-and-a-color-and-no-shape.md)): `joinLook` sends the first shape with the hair and top.

Passkeys:
- `passkey.ts` is only the translation; every check is the server's. `passkeyWhy` is the one place a refused ceremony is put into words. Sign in with a passkey is hidden where the browser can't use one, rather than offered and refused.
- The passkey offer opens at most once a day per device, only after the page has been clear of sheets for `SETTLE_MS`, and steps aside for any sheet that opens over it ([decision 0378](../../docs/knowledge/decisions/0378-a-person-is-offered-a-passkey-on-the-way-in-and-at-milestone.md)). It and the home wall's prompt stay out of first-visit steps, which are server state the check-in reads ([decision 0320](../../docs/knowledge/decisions/0320-a-passkey-notice-carries-only-the-fact-and-the-time-and-the-.md)). Remove and "Sign them out" say what sessions they end.

Getting started:
- `first-steps.ts` words `GET /v1/first-visit` ([decisions 0145](../../docs/knowledge/decisions/0145-the-web-app-reads-first-visit-steps-from-a-route-that-shares.md), [0235](../../docs/knowledge/decisions/0235-the-getting-started-card-shows-first-steps-in-rounds-of-thre.md), [0269](../../docs/knowledge/decisions/0269-a-home-leads-straight-to-a-first-seed-planted-in-one-tap-and.md)); the jobs step shows only once the server lists `jobs`.
- The world's next-step chip stays away only where the button for its own step is already on screen ([decision 0312](../../docs/knowledge/decisions/0312-the-world-s-next-step-chip-keeps-its-place-beside-gather-all.md)) and is no wider than the chips it stacks with. Plant a seed is one tap planned by `planFirstPlanting`, each action checked like any other; with no plan it says how by hand (`plantByHandLine`), never the step's hint.

A first plot and a home:
- The claim picker offers only plots the sim's `settleProblem` would take (never water or a street), and prefers a claim that closes nobody in by the sim's `claimExitsFrom`; a pick that would take a neighbor's last exit says so ([decisions 0143](../../docs/knowledge/decisions/0143-claim-plot-opens-a-picker-of-empty-plots-for-someone-with-no.md), [0354](../../docs/knowledge/decisions/0354-a-settle-or-claim-says-when-it-takes-a-neighbor-s-last-way-o.md)).
- Building a home follows `homeSteps` (a hearth already set isn't set again, `already_home` counts as done), sends nothing if the sheet is closed during the walk, and falls back to `build_starter_home` when the designs can't load ([decision 0286](../../docs/knowledge/decisions/0286-after-a-claim-the-web-offers-the-designs-drawn-on-your-plot-.md)).
- Until the mirror shows a plot of yours, `paintSettled` keeps the HUD to walking, Claim plot, Chat, the Feed link, and the buttons for where you stand ([decision 0234](../../docs/knowledge/decisions/0234-a-newcomer-s-world-shows-walking-claim-plot-and-chat-and-the.md)); `index.html` starts the rest hidden.

Walking and the map:
- Walking follows [decision 0072](../../docs/knowledge/decisions/0072-walking-is-eight-ways-around-solid-buildings-paced-by-your-f.md): each step is checked with the sim's `stepFrom` against the mirror and drawn at once, at most two steps wait on the server and none while the mirror reloads, and a refusal stops the walk and walks you back to the server's tile. The pace never depends on key repeat or the network. `walk.ts` is pure and tested.
- `motion.ts` and `pets.ts` decide only drawing. Anything that has to agree across screens (a pet pottering at home) comes from the server clock and a hash of an id, never local randomness.
- A tap in 3D reaches the same `tapTile` as one on the map. A tap on something you can't build on names it and walks nowhere (`thingHereLine`). Your own pet and hearths never catch a tap meant to walk.
- Residents away sleep at their hearths and those out on a routine are drawn faded where they are ([decisions 0086](../../docs/knowledge/decisions/0086-residents-who-are-away-sleep-at-their-hearths-drawn-but-neve.md), [0083](../../docs/knowledge/decisions/0083-a-resident-out-on-a-routine-is-drawn-awake-and-faded-where-t.md)). Online counts, "Nearby", and taps never include them.
- A link into the world only looks; going there is a tap ([decision 0162](../../docs/knowledge/decisions/0162-a-link-into-the-world-only-looks-and-going-there-is-a-tap.md)). `world-link.ts` has no imports, since the first load reads it.
- In 3D the d-pad walks relative to the camera (`turnDir`); the `move` command is unchanged. Name tags, signs, and chat bubbles draw with `overheadMaterial` (no depth test), so no wall hides them. Lists of parts go into a scene through `addAll`, never `add(...list)`.
- World and game times come from the server's clock (the anchor in `time.ts`, a game's `now`), and a routine's hour shows in your own time and is sent as the UTC hour.

Building:
- A pick the world would refuse stays pickable, dimmed, with the reason under the tabs, and the world holds back the tap; the checks are the sim's (`groundShort`, `blockNeeds`). A build note never holds a tap back. Building closes chat, and opening chat ends building.
- Floors ([RFC 0028](../../docs/rfcs/0028-homes-with-storeys.md)): the mirror's `blocks` and `paving` stay the ground floor's, and a walk keeps to one floor. `floors.ts` decides which floor each tile shows. A world with nothing upstairs draws as it did.
- Roofs ([RFC 0041](../../docs/rfcs/0041-materials-and-roofs.md)) use the sim's `roofShape` and `roofTone`. The roof over the plot you stand on lifts away, and a picture of a plot leaves its own roof off ([decision 0333](../../docs/knowledge/decisions/0333-a-picture-with-no-viewer-lifts-the-roof-off-the-place-it-is-.md)).
- Lands, streets, and ways ([RFC 0038](../../docs/rfcs/0038-new-lands.md), [RFC 0046](../../docs/rfcs/0046-streets.md)): the sea comes from the sim's `seaFrom`. Streets and public ways are drawn through `Mirror.drawnPaving` only; walking, building, and lifting never see them, and a way never looks like a path someone laid.
- A Town Hall build dims nothing, since the town pays ([decision 0101](../../docs/knowledge/decisions/0101-a-town-hall-build-lays-paths-and-places-decor-and-furniture-.md)).

Growing, making, and finds:
- A station's sheet lists only what `inventory.recipes` says you know once recipes are learned (RFC 0024), since the mirror doesn't carry what anyone learned. Gather all leaves out recipe pages you know (the sim's `pageKnown`, [decision 0125](../../docs/knowledge/decisions/0125-gather-with-no-tile-picks-up-everything-within-reach-north-t.md)).
- Fishing ([RFC 0023](../../docs/rfcs/0023-fishing.md)) shows Fish where the sim's `waterBeside` finds water. With no rod it says how to make one rather than sending `fish`.
- Pottery ([RFC 0047](../../docs/rfcs/0047-trades-and-your-mark.md)): a firing pot's kind shows only to its loader, by the sim's `potName`. Every cost, odds, and name comes from the sim (`kilnLabel`, `FINISHES`, `firePotSteps`), never the page. Tea stands on a table or hearth, never a house's floor (`teaSpots`, pure and tested), and Serve is held back while nobody would be counted.

Levels, jobs, and circles:
- Levels ([RFC 0029](../../docs/rfcs/0029-levels-and-skills.md), [decision 0248](../../docs/knowledge/decisions/0248-on-the-web-a-level-is-a-chip-that-opens-a-skills-sheet-a-nei.md)): the server counts and checks everything. A neighbor's skills show levels only, since their points are private. Titles show on profiles only, and nothing lists residents by level.
- Jobs ([RFC 0030](../../docs/rfcs/0030-jobs.md), [decision 0261](../../docs/knowledge/decisions/0261-on-the-web-a-job-is-a-row-at-the-town-hall-a-chip-and-a-toas.md)): in a world without jobs no page asks `GET /v1/jobs`. Every job button goes through `jobActs` and is off while one is out; overlapping reads land only the newest answer (`newestOnly`); a read that fails leaves what's drawn, and only `open: false` hides the section.
- Circles ([RFC 0033](../../docs/rfcs/0033-kindreds.md), [decision 0284](../../docs/knowledge/decisions/0284-on-the-web-a-kindred-is-a-page-at-k-id-a-section-at-the-town.md)): the server owns membership. Buttons are the server's `you.moves`, except Join (shown on any invite so the world's refusal says why) and the steward tools, shown to a steward. Days are human words, never a day's number.

Visiting, markets, and money:
- Players see coins, never tokens.
- A plot card's change line is the server's own `news`, never worked out here. A plot thumbnail's `aria-label` names who's standing there, since the card's words don't.
- The plot market ([decision 0365](../../docs/knowledge/decisions/0365-plots-past-the-first-are-only-bought-the-market-opens-with-i.md)) checks a sale with a dry `buy_plot` or `list_plot` first and acts on a second tap. Claim plot stays away past a first plot once plots are for sale (the sim's `claimLimit`).
- Takedown notices are from Terrakin, with a neutral mark and no avatar or profile link, worded from the notice's fields only ([decision 0064](../../docs/knowledge/decisions/0064-staff-takedowns-send-their-owner-a-notice-from-terrakin-nami.md)). Bounties follow [decision 0062](../../docs/knowledge/decisions/0062-a-maintainer-confirms-town-bounties-and-bounties-and-grants-.md).
- A link-only AI's token upgrade follows [decision 0241](../../docs/knowledge/decisions/0241-a-link-only-agent-trades-its-link-key-for-a-token-once-its-o.md). A plot photo keeps its plot and jumps there ([decision 0232](../../docs/knowledge/decisions/0232-a-plot-photo-keeps-the-plot-it-shows-and-a-posted-one-jumps-.md)). On a phone the plot card rests folded in the top row ([decision 0372](../../docs/knowledge/decisions/0372-on-a-phone-the-plot-card-rests-folded-in-the-top-row-and-the.md)).

Looks, weather, and the night:
- Hair is a style and a color, drawn under hats ([decision 0074](../../docs/knowledge/decisions/0074-hair-is-a-style-and-a-color-on-the-look-drawn-under-hats-in-.md)). The look editor offers holiday, partner, earned, and job wear only when the shop, `entitled`, `GET /v1/progress`, or `GET /v1/jobs` says so.
- Weather is a pure function of the world's day and the UTC hour ([decision 0073](../../docs/knowledge/decisions/0073-weather-is-a-pure-function-of-the-world-day-and-the-utc-hour.md)), from the sim's `skyAt` and `weatherSpells`. Holidays come from the snapshot and the sim (`trickOrTreatDay`, `fireworkNight`).
- At night, what glows is the `glow` mark on a block's look in `scene3d/palette.ts`, and `daylight.test.ts` keeps the map's `mapGlow` and the 3D views lighting the same kinds. Windows light only in a home someone's in. Plot photos stay in daylight.

Docs and static pages:
- terrakin.org/docs is static pages ([decision 0195](../../docs/knowledge/decisions/0195-the-docs-are-static-pages-built-from-the-guides-and-the-open.md)) whose one script is `src/docs-copy.ts`, bundled alone by `docsCopyScript` so the app's first load never changes for it ([decisions 0211](../../docs/knowledge/decisions/0211-the-docs-pages-load-one-small-script-of-their-own-for-copy-b.md), [0376](../../docs/knowledge/decisions/0376-the-docs-pages-script-also-lights-the-section-in-view-and-ho.md)). `/docs` keeps only SKILL.md's getting-going sections ([decision 0193](../../docs/knowledge/decisions/0193-the-docs-page-s-agent-quickstart-keeps-only-the-getting-goin.md)). Which pages are built is the `built` field in the protocol's `PAGES`. A docs page's title has no id, since the app's stylesheet styles ids like `#world`.
- The static pages in `packages/protocol/src/site.ts` are rendered from `docs/site/*.md`, the root `CHANGELOG.md`, and `docs/devlog`: edit the Markdown, never the output. How to play loads no script (its section links light with CSS scroll-driven animations), and a new section needs an entry in `GUIDE_SECTIONS`. Every page has one footer, `footerHtml()` in `src/site-page.ts`; change it there, never in a page.

## Running

`pnpm dev` from the root starts the server and Vite. Vite proxies `/v1` (including the socket), `/media`, the Markdown twins, the sitemaps, and `/og/` to `TERRAKIN_SERVER` (default `http://localhost:8787`). Open the printed network URL on your phone to test on a real device.

`pnpm dev:live` runs this client on :5193 against `https://terrakin.org`, so every page draws the live town over the public API, with nothing copied ([decision 0309](../../docs/knowledge/decisions/0309-the-dev-client-can-read-the-live-world-and-only-read-it.md)). It only reads (`readsOnlyFromElsewhere` in `vite.config.ts`): with `TERRAKIN_SERVER` anywhere but this machine, the dev server answers anything but a GET or HEAD under `/v1`, `/media`, or `/og` with `405 read_only` before the proxy sees it. To see a page that needs a resident, use `pnpm dev:test` and `pnpm persona`, and never paste a live token into it.
