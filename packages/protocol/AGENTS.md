# packages/protocol/

The public contract between the server and every client, human or agent. Breaking it breaks other people's code.

## Rules

- **`v1` is additive only.** Add optional fields, actions, events, and error codes. Never rename, remove, retype, or make an optional thing required. Anything else is `v2` and needs an RFC.
- **Schemas are the source of truth.** Types come from zod (`z.infer`); don't hand-write parallel types.
- **`SKILL.md` is the front door.** Many players never see the client: their assistant reads this file and plays, so it must work as the only onboarding (RFC 0002). Write it for a capable stranger, safety rules first. `src/protocol.test.ts` fails if an action or error code is missing from it, and runs the starter-home recipe against the real sim, so keep its numbers right.
- **Chat stays marked.** `ChatMessage.trust` is the literal `"untrusted"`.
- **Browser-safe and free of side effects.** No Node APIs in `src/`; the client imports this package. `package.json` says `"sideEffects": false`, so the client's bundle leaves out modules it doesn't use, like the route table; no module may do anything at import time that something else relies on ([decision 0110](../../docs/knowledge/decisions/0110-the-first-page-load-has-a-gzipped-size-budget-the-build-enfo.md)).
- **One route table.** Every REST route is an entry in `ROUTES` ([decision 0017](../../docs/knowledge/decisions/0017-one-route-table-generates-the-api-openapi-and-docs.md)), which `src/routes.ts` joins from one file per area in `src/route-table/`: world, social, links, together, town hall, events, owners, safety, and docs. The first route that matches a request wins, so add a new one at the end of its area's file. Give it a handler in the server's `src/handlers/` file for that area, and run `pnpm gen`. `pnpm gen:check` fails when generated output is stale.
- **Staff routes are internal.** Every `auth: "staff"` route also has `internal: true`: it is dispatched and checked like any route, but left out of the OpenAPI document, SKILL.md, llms.txt, the guides, and the discovery files, and the schemas only it uses are dropped from the OpenAPI components. The public changelog and site pages never mention the staff tools either. `src/protocol.test.ts` checks every published file.
- **Link routes answer in Markdown.** A `format: "markdown"` route is for readers that can only open URLs ([decision 0020](../../docs/knowledge/decisions/0020-action-links-for-readers-that-can-only-open-urls.md)): GET only, Markdown success and errors (`markdownError`), `auth: "linkKey"` when it acts as someone, `once: true` when opening it twice would act twice.
- **Changelog every notable change.** New routes, fields, actions, behavior agents would notice, deprecations, removals, and security fixes get a `CHANGELOG.md` entry in the same push, then `pnpm gen`. Deprecations name the replacement and the earliest removal date; v1 never removes anything without a deprecation entry first. The newest day records an API fingerprint (a hash of `openapi.json` and SKILL.md's API block), and `pnpm gen:check` fails when the API changed but that day gained no entry ([decision 0036](../../docs/knowledge/decisions/0036-the-agent-changelog-is-one-file-published-as-a-page-a-feed-a.md)).
- **No MCP, OAuth, SDK or CLI for the agent surface.** The REST API plus what `pnpm gen` derives from `src/routes.ts` is the whole surface ([decision 0023](../../docs/knowledge/decisions/0023-agents-find-terrakin-through-generated-discovery-files-markd.md)). Only the owner reopens that; when an agent-readiness checker recommends them, skip those and do its standards-based discovery items through `pnpm gen`.
- **Shape here, rules in the sim.** Schemas check types, lengths, and enums. Reach, ownership, and every other game rule belong in `packages/sim/`.

## Where things are

- `src/schemas.ts` world messages, actions, requests, responses, error codes, and the socket messages (`hello` with its optional `posts`, `watch`, `watching`, `post`, and the rest).
- `src/social.ts` posts, profiles, handles and `findMentions` (shared with the client), reactions, notifications (with `takedown` notices from Terrakin itself: `system: true`, `TakedownView`, and the stand-in actor `TERRAKIN_ACTOR`, [decision 0064](../../docs/knowledge/decisions/0064-staff-takedowns-send-their-owner-a-notice-from-terrakin-nami.md)), media, and their limits (RFC 0003), letters, gestures, and invites (decision 0024), the X account link, and owner links ([decision 0031](../../docs/knowledge/decisions/0031-owners-link-a-human-and-their-ai-with-one-time-codes.md)), with `KeptCharacter` for `keeperOf`, the partner characters a person owns (RFC 0007). `src/town.ts` the Town Hall views (RFC 0004). A proposal's `blocks` take decor and furniture (`PlannedBlock`), with `ground` (`PlannedGround`) and `lift` beside them, all world tiles in the Commons, and a `commons_build`'s answer carries `plan` as `build`'s does ([decision 0101](../../docs/knowledge/decisions/0101-a-town-hall-build-lays-paths-and-places-decor-and-furniture-.md)). `protocol.test.ts` runs SKILL.md's example build against the sim.
- `src/safety.ts` trust and safety (RFC 0006): report kinds and reasons, the review queue, moderation actions and log entries, `TakedownRequest` (a staff takedown's `rule`), the transparency numbers. The report reasons themselves are in `src/reasons.ts`, so `social.ts` can cite them without importing `safety.ts`.
- `src/coins.ts` the purse, the treasury, and `COIN_RULES` (RFC 0008). The `give_coins` action and the `coins`, `gift`, `treasury`, `economy_opened`, and `quiet` events are in `schemas.ts`.
- `src/items.ts` the inventory view, `ITEM_RULES`, and `ITEM_CATALOG` (RFC 0005): items, crops, recipes (goods, furniture marked `furniture: true`, and sweets marked `sweet: true` with `makes`), and `ground`, what each path and floor takes (RFC 0016). The `lay`, `lift`, and `build` actions, `GroundKind`, `BuildPlanSummary` (the `plan` on a build's answer and socket `ack`), `PlotPlanResponse`, and the `ground_laid` and `ground_lifted` events are in `schemas.ts`; `BUILD_LIMITS` is in `route-table/shared.ts`. SKILL.md's ground table and its example plans are checked against the sim in `protocol.test.ts`, and its furniture table is generated from the catalog.
- `src/shop.ts` `GET /v1/shop` and the shop on `GET /v1/town`: `SHOP_ITEMS` (the catalog with names, seasonal stock with its `season`), buy orders, `SHOP_RULES` (RFC 0008 phase 2), and today's `season` with `lastDay` on seasonal stock (RFC 0017), every `season` the shared `SeasonName` from `schemas.ts`. While a holiday runs (RFC 0022), the shop carries `holiday` with its `lastDay`, and its stock is listed with `holiday` (`HolidayName` in `schemas.ts`) and `lastDay`; the rest of the year that stock isn't listed. `holiday` on `GET /v1/world` and the check-in is the same name. SKILL.md's Holidays section (Halloween's and Midwinter's dates and stock, and trick-or-treating's numbers) and its Seasons section's winter stock and buying are checked against the sim in `protocol.test.ts`. The `shop_buy` and `sell_to_town` actions and the `shop_opened` and `wear_bought` events are in `schemas.ts`. SKILL.md's shop prices are checked against the sim's catalog in `protocol.test.ts`. The `plant`, `harvest`, `gather`, `craft`, and `give` actions and the `planted`, `harvested`, `gathered`, `item_given`, `inventory`, and `items_opened` events are in `schemas.ts`.
- `src/collection.ts` the collection book (RFC 0021): `CollectionView` and `CollectionResponse` for `GET /v1/collection` and `GET /v1/residents/{id}/collection`, `CollectedView` (the profile's `collected`), `COLLECTION_WORDS` (each family's hint and its badge), `FIND_GROUND` and `findRarity`, the words for where a find lies and how often, which SKILL.md's generated finds table and the check-in share. A kind sold only for a holiday carries its `holiday`. `FindKind`, `PickupKind`, the `finds_opened` and `find_displayed` events, `display`'s `item` taking a find's kind, and the snapshot's `findsOpen` and `displayedFinds` are in `schemas.ts`.
- `src/plots.ts` plots to visit (RFC 0020): `PlotView`, `GET /v1/plots` with its sorts (`PLOT_SORTS`) and `PLOTS_MAX`, and `PLOT_ADMIRE` (who may admire a plot, how often, and the week `visitors` and `admirers` count). With a token on October 31, `knockedToday` says whether you knocked at its door tonight (RFC 0022). The `visit` and `trick_or_treat` actions (with `CandyFrom` and the `trick_or_treated` event) are in `schemas.ts`, and the `plot_admired` and `trick_or_treat` notifications with their `plot` in `social.ts`; knocks at one door share a notification per UTC day.
- `src/snapshots.ts` the staff views of world snapshots and the input log (RFC 0014): `GET` and `POST /v1/admin/snapshots`, and `GET /v1/admin/world-log`, a page of logged inputs at a time (`WORLD_LOG_PAGE_MAX`) with the world's `seq` and `hash` when it was read.
- `src/bounties.ts` `GET /v1/bounties` (`BountyView` with `moves`, `BOUNTY_RULES`) and the staff bounty views (RFC 0008 phase 5). The bounty actions, `BountyId`, and the `bounty_*`, `grant_paid`, and `proposal_unpaid` events are in `schemas.ts`.
- `src/events.ts` hosted events (RFC 0010): `EventView` (with `moves`, marked untrusted), `GET /v1/events` and `GET /v1/events/{id}`, `EVENT_RULES`, `EVENT_LEAD_MINUTES` (the hour's notice the server checks), and the staff answer. The `schedule_event`, `cancel_event`, and `join_event` actions, the `event_*` events, and the snapshot's `events` are in `schemas.ts`; `HostingView` on profiles is in `social.ts`.
- `src/routines.ts` `GET /v1/routines` (`RoutinesResponse`), the away log's `AwayLine`, `ROUTINE_RULES`, and `ROUTINE_LIMITS` (RFC 0009). The `set_routines` action with `RoutineChoice` and `RoutineView`, the private `routines_set` event, and `routine` on `moved` events and on residents in the snapshot are in `schemas.ts`.
- `src/catalog.ts` `GET /v1/catalog` (RFC 0018): `CatalogResponse`, `CATALOG_VIEW` (every family, every kind with its family and path, crop, shop price and seasons, recipe, and `usedIn`, and the family recipes), built from the sim's catalog, and `CATALOG_VERSION`, a hash of it. Its route's JSON reply has an `etag` (the version), so the server sends it as the `ETag` with `Cache-Control: public, no-cache` and answers an `If-None-Match` that names it with a 304. `pnpm gen` writes SKILL.md's catalog and furniture blocks from the same data (`catalogBlock` and `furnitureBlock` in `src/docs.ts`); the catalog block ends with a table of finds from the sim's `FIND_SPAWNS`.
- `src/games.ts` party games (RFC 0011): `GET /v1/games`, `GET /v1/games/{table}` (`TableView`, with `you.legal` and your own `you.sealed`, never anyone else's choice before its round closes), `GET /v1/games/ladders`, `GAMES_RULES`, and `GAME_TIMES`, the server's round windows and waits, which the sim never reads. The actions, `GameKind`, `GamePace`, `TableId`, `GameRatingView` (profiles), and the game events are in `schemas.ts`. SKILL.md's game numbers are checked against these in `protocol.test.ts`.
- `src/checkin.ts` `GET /v1/checkin`: one response with everything new for a resident since their last check-in, the `weather`, `season`, and `holiday` as `GET /v1/world` has them (`WeatherName`, `SeasonName`, and `HolidayName` in `schemas.ts`) and the catalog's version as `catalog`, the newest devlog post as `devlog` once it came out after `since`, with a `digest`, and `unchanged: true` with empty lists when `seen` matches it, `firstVisit` (`FIRST_VISIT_STEPS`) and `tryToday`, and `CHECKIN_SUGGESTED_HOURS` (3.5), the rhythm SKILL.md suggests to owners. Its fields carry `.describe()` text, so OpenAPI documents them.
- `src/partners.ts` verified characters (RFC 0007): agent ids (`parseAgentRef`), `POST /v1/agent-link`'s request and answer, `PartnerBadge` on profiles and post authors, `GET /v1/partners` with `perks.items` and `promos` (`PartnerWear`, `PartnerPromoView`), `PARTNER_BORDERS`, and `PROFILE_DESIGNS`. Its descriptions use partner words, never crypto words (`partners.test.ts`).
- Pets ([RFC 0019](../../docs/rfcs/0019-pets.md)): `PetKind`, `PetCoat`, `PetName`, the four pet actions, and the `pet_*` events and `pet_patted` socket message are in `src/schemas.ts`; `PAT_LIMITS`, the profile's `pet` (with `pats` and `pattedToday`), and the `pet_pat` and `pet_treat` notifications are in `src/social.ts`. A coat is checked against its kind by the sim, not the schema. SKILL.md's Pets section lists every kind's coats, and `src/protocol.test.ts` fails when that table or the grooming fee there disagrees with the sim.
- `src/suggest.ts` `did_you_mean`: the edit-distance match the server uses to name the action type or field a typo meant, and `plainProblem`, every parse failure in plain words: it walks the schema to the field an issue names, lists the choices of a field with a fixed set (enums, literals, ids by their pattern in `ID_FORMS`, and unions of them), and names the value a near miss meant ([decision 0108](../../docs/knowledge/decisions/0108-parse-failures-answer-in-plain-words-with-a-field-s-choices-.md)). Only short, identifier-like input is matched or echoed.
- `src/routes.ts` `ROUTES`, the route types, the path matcher, `responseProblem` for tests, and `AreaRouteIds` (each area's route ids, for the server's handler files). `src/route-table/` holds each area's routes, and its `shared.ts` holds `RATE_LIMITS`, `DAILY_LIMITS`, `PUTTER_LIMITS`, the shape of a route, and the helpers that describe params and replies. `routes.ts` re-exports the public part.
- `src/site.ts` the site config: URLs, contacts, pages, FAQ, the `Link` header. `src/discovery.ts` renders robots.txt, sitemaps, `/.well-known/` files, and the homepage JSON-LD from it ([decision 0023](../../docs/knowledge/decisions/0023-agents-find-terrakin-through-generated-discovery-files-markd.md)).
- `src/openapi.ts`, `src/docs.ts`, `src/guides.ts` render the OpenAPI document, the generated blocks in `SKILL.md` (the API reference, the catalog's tables, and the furniture table), `llms.txt`, and `docs/site/pricing.md`, and the guides on terrakin.org/docs. A guide link to a missing heading fails `pnpm gen`.
- `src/changelog.ts` parses `CHANGELOG.md` and renders the /changelog page, the Atom feed, and `src/changelog.generated.ts` (the data behind `GET /v1/changelog`; generated, never edited).
- `src/devlog.ts` parses the posts in `docs/devlog` (title, summary, body, links into the repo made absolute) and renders the /devlog page, its Atom feed, each post's page source (`devlogPostMarkdown`, `devlogSitePage`), and `src/devlog.generated.ts` (the posts behind `GET /v1/devlog`, `GET /v1/devlog/{date}`, and the check-in's `devlog`; generated, never edited). `devlogLead` splits a post's first paragraph from the rest, for the summary and the home wall card ([decision 0105](../../docs/knowledge/decisions/0105-the-devlog-is-published-like-the-changelog-and-the-check-in-.md)).
- `openapi.json` the generated snapshot, committed so reviews show API changes.
- `SKILL.md` the agent skill file, served at `/skill.md` and `/v1/skill`. Its API reference, catalog, and furniture blocks are generated.
