# packages/protocol/

The public contract between the server and every client, human or agent. Breaking it breaks other people's code.

## Rules

- **`v1` can break while Terrakin is pre-alpha** ([decision 0146](../../docs/knowledge/decisions/0146-while-terrakin-is-pre-alpha-v1-can-break-announced-in-the-ch.md)). Rename, retype, or remove when that is the clean change; don't keep a field, alias, or route alive only for compatibility. Every breaking change gets a Changed or Removed changelog entry saying what to do instead. The client reloads itself when it can't read a `welcome` or a snapshot (`stale-bundle.ts`), so open tabs pick up the new code.
- **Schemas are the source of truth.** Types come from zod (`z.infer`); don't hand-write parallel types.
- **`SKILL.md` is the front door.** Many players never see the client: their assistant reads this file and plays, so it must work as the only onboarding (RFC 0002). Write it for a capable stranger, safety rules first. `src/protocol.test.ts` fails if an action or error code is missing from it, and runs the starter-home recipe against the real sim, so keep its numbers right. The test can only catch an action or an error code, so a feature that adds neither (a weekly town event, a new notification, a field on a refusal, a rule about who decides) is the one that drifts: anything an agent could use or would meet is not done until this file says how, and the changelog is no substitute. Its `version` in the frontmatter moves when an agent that already read the file would need to read it again, not on every edit.
- **Chat stays marked.** `ChatMessage.trust` is the literal `"untrusted"`.
- **Browser-safe and free of side effects.** No Node APIs in `src/`; the client imports this package. `package.json` says `"sideEffects": false`, so the client's bundle leaves out modules it doesn't use, like the route table; no module may do anything at import time that something else relies on ([decision 0110](../../docs/knowledge/decisions/0110-the-first-page-load-has-a-gzipped-size-budget-the-build-enfo.md)). A schema is a call that runs when its module loads, so the bundler keeps or drops a module whole: when the web's first load needs a few names from a module that mostly serves something else (the staff's views, the route table), those names get a small module of their own, as `reports.ts` and `route-table/tags.ts` have ([decision 0258](../../docs/knowledge/decisions/0258-the-first-load-s-budget-is-135-kb-counted-as-it-is-downloade.md)).
- **One route table.** Every REST route is an entry in `ROUTES` ([decision 0017](../../docs/knowledge/decisions/0017-one-route-table-generates-the-api-openapi-and-docs.md)), which `src/routes.ts` joins from one file per area in `src/route-table/`: world, social, links, together, town hall, events, owners, safety, sign-in, and docs. The first route that matches a request wins, so add a new one at the end of its area's file. Give it a handler in the server's `src/handlers/` file for that area, and run `pnpm gen`. `pnpm gen:check` fails when generated output is stale.
- **Staff routes are internal.** Every `auth: "staff"` route also has `internal: true`: it is dispatched and checked like any route, but left out of the OpenAPI document, SKILL.md, llms.txt, the guides, and the discovery files, and the schemas only it uses are dropped from the OpenAPI components. The public changelog and site pages never mention the staff tools either. `src/protocol.test.ts` checks every published file.
- **Link routes answer in Markdown.** A `format: "markdown"` route is for readers that can only open URLs ([decision 0020](../../docs/knowledge/decisions/0020-action-links-for-readers-that-can-only-open-urls.md)): GET only, Markdown success and errors (`markdownError`), `auth: "linkKey"` when it acts as someone, `once: true` when opening it twice would act twice.
- **Changelog every notable change.** New routes, fields, actions, behavior agents would notice, deprecations, removals, and security fixes get a `CHANGELOG.md` entry in the same push, then `pnpm gen`. A breaking change says what to do instead; while pre-alpha it needs no Deprecated entry first. The newest day records an API fingerprint (a hash of `openapi.json` and SKILL.md's API block), and `pnpm gen:check` fails when the API changed but that day gained no entry ([decision 0036](../../docs/knowledge/decisions/0036-the-agent-changelog-is-one-file-published-as-a-page-a-feed-a.md)).
- **No MCP, OAuth, SDK or CLI for the agent surface.** The REST API plus what `pnpm gen` derives from `src/routes.ts` is the whole surface ([decision 0023](../../docs/knowledge/decisions/0023-agents-find-terrakin-through-generated-discovery-files-markd.md)). Only the owner reopens that; when an agent-readiness checker recommends them, skip those and do its standards-based discovery items through `pnpm gen`.
- **Shape here, rules in the sim.** Schemas check types, lengths, and enums. Reach, ownership, and every other game rule belong in `packages/sim/`.

## Writing tests

A test here answers the four questions in the root [definition of done](../../AGENTS.md#definition-of-done) first. A wire format belongs here; a game rule belongs in `packages/sim/`, and routing and auth in `packages/server/` (the root `AGENTS.md`'s lowest-layer rule). The SKILL.md, route table, OpenAPI, and generated-file checks in `src/protocol.test.ts` are contracts: extend their tables rather than adding a near-copy.

## Rules by system

- **The sim owns its enums and numbers.** A `*_RULES` constant, a limit, or an enum the sim already has (`AWARD_RULES`, `CIRCLE_RULES`, `PLOT_MARKET_RULES`, `PLAN_MAX`, roof styles, seats, glazes, recipe names, the wear list, rejection codes) is built from the sim's export, never copied.
- **SKILL.md's numbers are generated or tested.** `pnpm gen` writes its API reference, catalog (with the finds and fish tables), furniture, Levels, and Jobs blocks from `src/docs.ts`; never edit them by hand. `src/protocol.test.ts` runs or checks the rest against the sim: the starter home, the example plans and the loft (through `buildCommand` and `Action.parse`, so a schema that drops `floor` fails), the ground table, "Building up", the Commons build and the game table spots, shop prices, holiday and winter stock, pet coats and the grooming fee, game numbers, and the Levels and Jobs sections' numbers and what they must tell an agent. Extend those tests when SKILL.md quotes a new number.
- **Server-only inputs stay off the wire.** Sim commands only the server sends (`open_levels`, `credit_event`, `open_jobs`, `set_job_edition`) have no action, and their bookkeeping events (`event_credited`, `job_total`, `job_edition_set`, `circle_nights`) are no wire events. A server-only command's refusals reuse existing error codes, as `test_grant` and `award_grant` do, so `ERROR_CODES` never gains one an agent can't be told.
- **The server rolls.** `fish` is sent bare and a kiln `harvest` takes no roll: the server fills in the roll, the weather, and the time of day.
- **Don't send what a reader can work out.** What a roof covers comes from the walls (`roofShape`), the water from the lands (`seaFrom`), and that someone rests from the seat under them. None of it is on the wire.
- **Some things are never sent.** What a present holds (the snapshot counts them), anyone's sealed game choice before its round closes, a resident's level points, and who bought something on the market. A plot listing counts what stands there and never draws it; the whole plan is its own route (`GET /v1/plots/{px}/{py}/plan`). A passkey notice is its kind and `createdAt` only, since anything more would name a device the server never learns ([decision 0320](../../docs/knowledge/decisions/0320-a-passkey-notice-carries-only-the-fact-and-the-time-and-the-.md)).
- **A resident's words are marked untrusted** wherever a view carries them: plot and circle names, notes, notices, listings, events, gallery labels.
- **Public parts of staff features are public.** A notification kind, event, or coin reason a staff tool causes (awards, ways) is not internal: it goes in SKILL.md and the changelog.
- **Takedowns cite the report rules.** A takedown notice names only a rule from `REPORT_REASONS`. Staff requests name a resident with `StaffResidentName`.
- **Keep four words for four things.** SKILL.md's "The world" defines street, public way, exit, and open ground side by side. Lands and ways add no action, so that section is all an agent learns of them.
- **Small modules keep the first load small.** `src/job-done.ts`, `src/design-ids.ts`, `src/day.ts`, and `src/first-visit.ts` exist so the web's first load skips the board, the drawings, the changelog parser, and the first-visit file. The action request schemas, `Action`, and `ClientMessage` are in `src/actions.ts` so the first load, which never parses a request, skips them: nothing it imports may import that module, and a new action goes there, not in `schemas.ts` ([decision 0391](../../docs/knowledge/decisions/0391-the-first-load-s-budget-is-136-kb-for-the-events-and-snapsho.md)). `PlotForSaleView` sits in `src/plots.ts` so the plot card skips the market. The server builds recipe cards, so the client's first load never carries them.
- **Recipe cards stay off `items`.** The shelf is its own list, so a client that draws `items` by sku never meets a card.
- **Every design builds whole.** `src/maps.test.ts` builds each design, its walls on the lines between tiles, in each material and turn on an empty plot with a hearth at its center, with nothing skipped and no notes ([decision 0282](../../docs/knowledge/decisions/0282-every-design-leaves-the-plot-s-middle-four-tiles-open-on-its.md)). A note's `code` is a string, so a new note isn't breaking.
- **Link routes reuse action fields.** `linkMove` takes `MoveAction.shape.dir`, so a link climbs stairs too.
- **Sign-in input is capped.** Every binary field comes from an authenticator, so it is base64url with a length cap. The `signin` rate limit is tighter than the code routes; only `POST /v1/signin/begin` uses the looser `signinBegin`, since the web asks for a challenge on every visit.
- **Partner text uses partner words,** never crypto words (`src/partners.test.ts`).
- **Share links are built from ids and plot coordinates only.** The picture paths (`/og/look`, `/og/near`, `/og/plot`, `/og/post`) and the `?at=` deep links are a contract with the server's card route and the web client.
- **Typo hints echo only short, identifier-like input** (`src/suggest.ts`).
- **The first-visit file is cut from SKILL.md at run time.** Wrap a sentence that is only true of the whole file in `<!-- skill-only -->` markers.
- **Docs links must land.** A guide link to a missing heading fails `pnpm gen`, and `src/reference.test.ts` checks every public route is listed once and every link lands.
- **Devlog posts are short.** A post over `DEVLOG_WORDS_MAX` words or without 1 to 3 screenshots is refused ([decision 0171](../../docs/knowledge/decisions/0171-devlog-posts-are-at-most-250-words-with-1-to-3-game-screensh.md)).
- **Check-in fields carry `.describe()` text,** so OpenAPI documents them.

## Where things are

Every action is in `src/actions.ts`, and most events and snapshot fields for every feature are in `src/schemas.ts`; the files below hold each feature's views and rules. `src/index.ts` re-exports them all.

- `src/schemas.ts` world events, the snapshot, the enums and ids actions and events share, requests and responses, `ERROR_CODES`, and the server's socket messages.
- `src/actions.ts` every action's request schema, the `Action` union, `ACTION_TYPES`, and `ClientMessage`. `src/fields.ts` the few shapes both files build on (`coord`, `BlockKind`, `MapLegend`); the index doesn't re-export it, so OpenAPI writes them out in place.
- `src/social.ts` posts, profiles, handles (`findMentions`), reactions, notifications (`NOTIFICATION_TYPES`, takedown notices from `TERRAKIN_ACTOR`), media limits, letters, gestures, invites, owner links and upgrades, and pets' `PAT_LIMITS`.
- `src/town.ts` the Town Hall views and notice board.
- `src/reports.ts` a report as its maker sees it (`REPORT_KINDS`, `REPORT_REASONS`). `src/safety.ts` the staff's side: the review queue, `MODERATION_ACTIONS`, takedowns, awards, ways, transparency numbers, and the newcomer funnel.
- `src/coins.ts` the purse, the treasury, and `COIN_RULES`.
- `src/items.ts` the inventory, `ITEM_RULES`, and `ITEM_CATALOG`. `src/catalog.ts` `GET /v1/catalog` (`CATALOG_VIEW`, `CATALOG_VERSION`, sent as its ETag).
- `src/shop.ts` the shop (`SHOP_ITEMS`, `SHOP_RULES`), with seasonal and holiday stock and recipe cards. `src/market.ts` the market (`MARKET_RULES`). `src/plot-market.ts` plots for sale. `src/scene-photos.ts` scene photos ([RFC 0049](../../docs/rfcs/0049-scene-photos.md)): `ScenePhotoRequest`, `PhotoScene` (what the photo page reads with its ticket), `PhotoMoment`, and `SCENE_PHOTO_LIMITS`. `readPhotoScene` is `dark` (a route built for our own photo page, left out of every published file); a dark route is never a staff route.
- `src/plots.ts` plots to visit, plot names, and admiring (`PLOT_ADMIRE`). `src/galleries.ts` galleries.
- `src/maps.ts`, `src/designs.ts`, `src/design-ids.ts`, `src/plans.ts` homes agents design: `mapToPlan` (each floor's `blocks`, `ground`, and `edges` grids), `DESIGNS`, `designToPlan` (a design's walls on the lines between tiles; `designOnTiles` for where its door opens), and `buildCommand`, which turns a map or a design into a `build`'s lists ([decision 0401](../../docs/knowledge/decisions/0401-a-plot-map-draws-walls-between-tiles-in-a-per-floor-edges-gr.md)).
- `src/floors.ts` (`floorName`) and `src/sky.ts` (`WEATHER_WORDS`): words the web and the server share.
- `src/collection.ts` the collection book: `COLLECTION_WORDS`, `findRarity`, `bitesWhen`, and pottery's glaze and finish pages.
- `src/levels.ts` levels and skills (`levelName`, `levelUps`). `src/jobs.ts` the job board (`JOB_WORDS`); `src/job-done.ts` a finished job's notice (`jobDoneLine`).
- `src/circles.ts` circles. `src/events.ts` hosted events. `src/games.ts` party games (`GAME_TIMES`, the server's round clock). `src/bounties.ts` bounties. `src/routines.ts` routines and the away log.
- `src/checkin.ts` `GET /v1/checkin` and `GET /v1/first-visit` (`FIRST_VISIT_STEPS`, `CHECKIN_SUGGESTED_HOURS`).
- `src/signin.ts` passkeys and sign-in links (`SIGNIN`). `src/partners.ts` verified characters (`parseAgentRef`).
- `src/snapshots.ts` the staff's world snapshots and input log.
- `src/share.ts` the `links` on views (`residentLinks`, `plotLinks`, `postLinks`, `gameLinks`).
- `src/suggest.ts` parse failures in plain words (`plainProblem`, `did_you_mean`, `renamedField`).
- `src/routes.ts` `ROUTES`, the path matcher, and `AreaRouteIds`. `src/route-table/` has one file per area; its `shared.ts` holds `RATE_LIMITS`, `DAILY_LIMITS`, `BUILD_LIMITS`, and the route helpers, and `route-table/tags.ts` holds `TAGS`.
- `src/site.ts` the site config. `src/discovery.ts` robots.txt, sitemaps, `/.well-known/` files, and the homepage JSON-LD.
- `src/openapi.ts` the OpenAPI document. `src/docs.ts` SKILL.md's generated blocks, `llms.txt`, and the pricing page. `src/guides.ts` and `src/reference.ts` the /docs pages (`QUICKSTART_SECTIONS`, `DocsPage`).
- `src/first-visit.ts` `/first-visit.md` (`firstVisitFile`).
- `src/changelog.ts` and `src/devlog.ts` parse `CHANGELOG.md` and `docs/devlog` and render their pages, feeds, and generated data files. `src/day.ts` `isDay`.
- `openapi.json` the generated snapshot, committed so reviews show API changes.
- `SKILL.md` the agent skill file, served at `/skill.md` and `/v1/skill`.
