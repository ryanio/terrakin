# packages/server/

The front door. Parses, authenticates, rate limits, runs the sim, persists, and broadcasts. It holds no game rules. How the pieces fit: [docs/architecture.md](../../docs/architecture.md).

## Rules

### The world

- Every world change goes through `WorldService.run()`: `prepare` (check), `store.appendInput` (persist), `commit` (mutate), broadcast. A failed write never leaves memory ahead of the log. Never mutate `service.state` directly. A dry run (`dry: true`) goes through `act()` and `run(input, true)` like a real one and stops after `prepare`; an offline resident is checked against the sim's `asJoined` view, and nothing brings them back online. `hash()` is cached per `seq`, which is only safe because nothing else changes the world.
- Purses, inventories, points, and jobs are private. The events in `PRIVATE_EVENTS` (`world-wire.ts`) go only to the resident they name (a lesson's `recipe_learned` to its teacher too), never in a broadcast or anyone else's answer. Use `eventsFor` and let `run()` route them. A profile shows levels and a title, never points, today's counts, or firsts; those are `GET /v1/progress`'s, which answers only its own caller.
- Each system a world opens with a logged switch is absent from the wire of a world that never logged it, so such a world reads as it always did. Keep a new field behind its state (`state.progress`, `state.jobs`, `state.circles`, `clayOpen`, `lands`). `levels.test.ts`, `jobs.test.ts`, `circles.test.ts`, and `pottery.test.ts` pin the reads of a world without the switch key by key.
- `tick()` logs each one-time switch from one table: `PRESENCE_SWITCH`, then `DAY_SWITCHES` in order, each with its option, `due`, command, and label, run by `switchOn`. A new switch goes in the table where it has to come.
- Which switches each adapter sets. The shared ones are `WORLD_SWITCHES` (`src/world-switches.ts`), which both spread; the Worker adds its own after the spread, each with why. `world-switches.test.ts` pins what each adapter runs.
  - Levels, jobs, circles, recipes, shop, shop in person, holiday prices, presence, and the rest of the day table: both adapters ([decision 0373](../../docs/knowledge/decisions/0373-every-node-world-opens-the-systems-terrakin-org-runs-recipes.md)). Jobs wait for levels; circles for coins. `jobEdition` moves the board forward only, with one `set_job_edition` right after a `new_day`, never mid-day ([decision 0265](../../docs/knowledge/decisions/0265-the-jobs-board-s-second-edition-a-lane-s-regular-jobs-carry-.md)).
  - Pottery (`clay`) and new lands (`lands`): the Worker only, so self-hosting, `pnpm dev`, and the e2e servers have neither ([decision 0371](../../docs/knowledge/decisions/0371-pottery-is-on-at-terrakin-org-the-worker-sets-clay-the-node-.md), [RFC 0038](../../docs/rfcs/0038-new-lands.md)).
  - Plots for sale (`plotMarket`): neither, until Ryan says go ([decision 0365](../../docs/knowledge/decisions/0365-plots-past-the-first-are-only-bought-the-market-opens-with-i.md)).
  - A test world opens these now through the loopback-only test routes (`testOpenClay`, `testOpenLand`, `testOpenPlotMarket`) or `pnpm persona --open-clay`, `--open-land`, `--open-plot-market`.
- Once clay is out, `moveJobEdition` moves the board one edition a `new_day` on to the sim's `POTTERY_JOB_EDITION`, never mid-day and never skipping one.
- The lands switch opens nothing on its own: it logs `open_land` each time the claimable plots left fall to the sim's `LANDS.openAt`, a count and never a date, until `LANDS_TO_OPEN` runs out. `planLand` puts every number in the input, so replay never plans. A land's name comes from that fixed list, never a resident. `planProblem` refuses a plan with no streets, a slot no walk from the Commons reaches, or, fully claimed, a plot with no way out ([decision 0357](../../docs/knowledge/decisions/0357-a-land-plan-is-refused-when-fully-claimed-a-plot-has-no-way-.md)).
- The town centre reads `downtown(state)`, never `config.width`/`config.height`, which `open_land` grows. Passing the grown config is a type error.
- The board is data: no `todo` line asks for a job, and the board never goes in the check-in's digest. Names and notices are resident text: no `todo` line quotes one.
- A forming circle is hidden from outsiders. Invites go only to the invitee and stewards, a forming circle's events only to its members, invitees, and the resident named (`circleAudience`, with `circleRoster` for a circle the commit disbanded), and an outsider naming one hears what a missing id gets (`hiddenCircle`). A report takes only a formed circle.
- Rolls the server adds to an input (a cast's `castRoll`, a kiln's `fairRoll`) use Web Crypto, rejection sampled. A dry run rolls nothing.
- What a resident hears about a pot comes from their own events: `fired` is read from the actor's own `inventory` event, so a co-owner opening someone else's kiln hears no pot, and `pot_sold` carries codes and numbers, never the buyer or the label.
- Lengths of time (`MINUTE_MS`, `HOUR_MS`, `DAY_MS`) and `utcDay` come from the sim's `clock.ts`. No file here defines its own.

### Routes, errors, and storage

- Routes come from the table. Add the route to its area's file in the protocol's `src/route-table/` and its handler to that area's file in `src/handlers/` (a link route's in its feature's file in `src/links/`, id in `LinkRouteId`), then run `pnpm gen`. Handlers are typed by `AreaRouteIds`, so a missing or extra one is a compile error. `routeHandlers()` spreads `linkHandlers` last, so a route handled twice quietly uses the `links/` one. No path matching anywhere else. The dispatcher parses every input with the protocol schemas.
- Errors are `{ error: { code, message } }` with a code from `ERROR_CODES` and a message a player could read. A typo in an action type or field gets `did_you_mean` (`suggestFor`); actions refuse a near-miss field even when the rest parses, and every other body refuses a renamed field (`renamedField`). Every other parse failure, in a body, query, path, or socket action, is answered by `plainProblem` ([decision 0108](../../docs/knowledge/decisions/0108-parse-failures-answer-in-plain-words-with-a-field-s-choices-.md)), never zod's message. A family recipe's thing for a kind outside its family gets the world's `unknown_item` answer (`familyMiss`), on REST and the socket.
- Ids from requests are own keys. Look world records up with the sim's `own`, `residentById`, `listingById`, `goodById`, or `findBounty`, never `state.x[id]`. `SocialService` refuses inherited ids before its lookup. `ids.test.ts` sends them to every route that takes one.
- `CREATE TABLE IF NOT EXISTS` is a first boot, never a migration. A column added to an existing table needs an `ALTER TABLE ... ADD COLUMN` beside it, run every boot in a `try`/`catch`; a table whose columns come from a constant needs that pass over the same constant ([learning](../../docs/knowledge/learnings/2026-10-20-a-column-added-to-a-create-table-if-not-exists-never-reaches.md)). `schema-upgrade.test.ts` boots storage on every table as it first shipped (`src/first-tables.ts`). A new table adds its `CREATE TABLE` there as it ships, and an entry there is never edited to match the code. Anything else read back from before a deploy gets a test that starts from the old shape.
- SQL fits a Durable Object's limits: at most 5 terms in a compound SELECT, 100 bound values, and 100,000 bytes a statement (`SQL_LIMITS` in `src/sql-store.ts`). `nodeSql` refuses them too, so tests catch it. Read ids from many tables with `idsFrom`, never one long `UNION`, and cap or split any `IN (...)` list built from input ([learning](../../docs/knowledge/learnings/2026-10-08-a-durable-object-s-sqlite-refuses-a-union-of-more-than-5-ter.md)).
- Never throw out of a socket callback. The `message` handler catches and replies `internal`.
- Every ask of the World object from the Worker goes through `askWorld` (`src/pages.ts`, [decision 0292](../../docs/knowledge/decisions/0292-a-read-a-world-object-restart-broke-goes-again-once-and-a-fa.md)). A GET or HEAD that isn't a socket upgrade goes again once after a broken connection, a write never does, and one still unreachable is `unavailable` (503) reported as `world.fetch`. The body is read before it returns (`inHand`), since a stub's `fetch` settles on its headers ([learning](../../docs/knowledge/learnings/2026-10-17-a-durable-object-stub-s-fetch-settles-on-its-headers-so-a-br.md)). An error the object threw itself goes on through.
- A new client route needs a case in `matchPage` (`src/page-meta.ts`), or its HTML goes out as a 404 with `noindex`.
- Inject time and the network. Anything time-based takes a `now()`, and the X reader, agent link network, and card readers are injected, so tests never sleep or touch the network.
- Client IPs come from `clientIp()` on Node and `CF-Connecting-IP` on Cloudflare. Never read `X-Forwarded-For` anywhere else.
- Both runtimes. Code the Worker imports (`api.ts`, `api-response.ts`, `api-wiring.ts`, `live.ts`, `townsfolk-status.ts`, `handlers/`, `links/`, `world-service.ts`, `world-actions.ts`, `world-credentials.ts`, `world-wire.ts`, `snapshots.ts`, `sql-store.ts`, `social-service.ts`, `x-link.ts`, `media.ts`, and what they import) uses no `node:fs` and no `Buffer`; `pnpm typecheck` checks it against the Workers types. It never stores a runtime global as a field: workerd refuses its own `fetch` called as a method of anything else. Default an injected fetch to `options.fetch ?? ((input, init) => fetch(input, init))` and cover the default with a test ([learning](../../docs/knowledge/learnings/2026-10-20-workerd-refuses-a-stored-global-fetch-so-musegod-heard-nothi.md)).

### Credentials and staff

- Tokens, link keys, codes, and staff keys are stored as SHA-256 only, never logged, and shown once. Hash through `src/bytes.ts` (`sha256Hex`, `sha256HexSync`) and nowhere else, since stored credentials are found by that hex (`bytes.test.ts`). Link keys travel in the URL path, so mask `/v1/act/<key>` before a path reaches a log line or an error.
- A link route must not reach uploads, deletes, or key minting. A link key becomes a token only through `POST /v1/link-key/upgrade/token`, with its owner's approval ([decision 0241](../../docs/knowledge/decisions/0241-a-link-only-agent-trades-its-link-key-for-a-token-once-its-o.md)).
- Staff identity comes only from the Worker ([decision 0040](../../docs/knowledge/decisions/0040-a-staff-app-on-its-own-host-behind-cloudflare-access-with-st.md)). Staff routes are `auth: "staff"`. With Access configured, the only staff email is the one the Worker verified from the Access JWT and passed in `STAFF_EMAIL_HEADER`, which `toWorld()` drops from every incoming request first. Never read the header anywhere else, and never let a resident token count when Access is on. `staffFor` refuses `cross-site` requests, any `Origin` but the admin host's, and writes that aren't JSON.
- A staff key (`tks_`, [RFC 0026](../../docs/rfcs/0026-staff-keys.md)) acts as its maker (`staffOwner`), never beyond their role now or the key's scope (`keyAllows`), and never reaches the key routes, the world-log export, or anything in `KEY_NEVER`. Every role check, `staffResident`, and `worldStaffId` reads the maker through `staffOwner`; a new one must too.
- The deploy's Access service token ([decision 0257](../../docs/knowledge/decisions/0257-ci-s-deploy-signs-in-for-the-replay-check-with-an-access-ser.md)) is honored only for `TERRAKIN_ACCESS_DEPLOY_CLIENT`, only on an admin host, only for a GET of the world log (`adminGate`, `DEPLOY_ACTOR`). It passes in `STAFF_SERVICE_HEADER`, which `toWorld()` drops like the email header. It has no role: never give it one or name it in another route. `staff.test.ts` pins every way `cloudflare/worker.ts` hands a request to the World object.
- Moderation actions are logged. Staff or triage acting on someone else's content goes through `SafetyService`, which writes the append-only `moderation_log` with a reason and the actor ([decision 0033](../../docs/knowledge/decisions/0033-reports-auto-hide-suspensions-and-an-append-only-moderation-log.md)). Its console line names an Access sign-in only as `staff`. In the world log, `worldStaffId` turns a sign-in into an opaque `staff_` id, so no email is ever logged there.
- Auth, sessions, rate limits, and the store are security-sensitive: run the `reviewer` subagent.

### Resident text and outside data

- Resident text goes through `cleanText()` and `Moderation.review()` (`src/moderation.ts`, [decision 0032](../../docs/knowledge/decisions/0032-lite-text-filters-at-the-edge.md)) before it's stored, logged in the world, or sent: pick its `Surface`, pass the resident (and `ipKey()` for posts), and call `commit()` once stored. A new door for text needs a line in `src/trust-safety.test.ts`. Report notes run only the check for orders aimed at AI readers, since a fair note may quote what was said. Never log the text a filter saw, only its category, surface, and resident id.
- `injection.ts` turns away text written as orders to AI readers, owner codes, sign-in links, write requests to the API, and link keys ([decision 0014](../../docs/knowledge/decisions/0014-turn-away-text-aimed-at-ai-readers-and-strip-image-metadata.md)). Page meta writes resident text only through escaping APIs.
- Words we write about the world (plot news, photo stories, away lines, check-in `todo` lines, notices from Terrakin) are built from counts, codes, and ids, never from anyone's text.
- Blocks and suspensions apply everywhere a resident reaches another: a gift, give, sale, claim, sit, teach, invite, visit, knock, cast, or event join across a block is refused, and lists leave out suspended residents and anyone blocked either way. The one exception is the public plot list, which leaves out only those the caller blocked (`blockedBy`), since leaving out those who blocked the caller would tell them who did. Counts never say who. A recognition award skips the block check on purpose: it is a payment, not contact.
- Anything a network or an agent card sends is untrusted ([decision 0050](../../docs/knowledge/decisions/0050-agents-prove-themselves-from-their-registry-and-card-and-par.md)). Decode strictly, keep only the card's `name` (cleaned and filtered) and its `terrakin` endpoints, and never store, log, or show the rest. Matching reads who holds the agent, never the card's text. No holder address is stored: the agent's holder is compared and dropped, a character's kept only as a hash. Every read goes through `AgentLinkService`, which reserves from that day's pool before reading (`agent-links.test.ts`). On Node, card fetches go through `node-net.ts`, which refuses private addresses on the connection. A partner character's picture comes only from partner config, is fetched by the same rules (`fetchOutside`), must be an image by type and bytes, and is stored only through `upload()` ([decision 0058](../../docs/knowledge/decisions/0058-partner-characters-wear-a-curated-border-and-profile-design-.md), `partner-art.test.ts`).
- Only a resident's own agent link ask is ever finished: never link from a card alone.
- Anything X sends is untrusted. Store only the handle and the post link; never store, log, or show its HTML ([decision 0022](../../docs/knowledge/decisions/0022-connect-an-x-account-by-reading-a-public-post-no-oauth.md)).
- Uploads are hostile bytes. A parser for an upload format reads every length unsigned (`|` and `<<` are signed, so a 32-bit length ends in `>>> 0` or is read with a `DataView`), checks it against its parent before using it, never allocates from an unchecked length, caps how many items it records and holds no object per item it only copies, keeps its work linear in the file's size, refuses rather than throws, and gets a truncation and random-corruption test plus a cap-sized hostile file (`strip-metadata.test.ts`, `image-size.test.ts`, `passkeys.test.ts`). Uploads are parsed in the World object, so a blowup resets the world for everyone. Removed metadata is overwritten in place with padding, so media data and its offsets stay put ([decision 0043](../../docs/knowledge/decisions/0043-strip-video-and-model-metadata-in-place-and-refuse-what-can-.md)).

### Money and telemetry

- Caps that guard money ship with a test that proves they refuse (see "upload cost guards" in `social.test.ts`). The last test in front of a guard is never deleted.
- Triage spends money. Every call goes through `TriageClient.classify()`, which checks the key, the daily call and token caps, the share kept for reports, and the breaker before it fetches; `SafetyService` takes a slot (`takeTrigger`) first. A new path to the model goes through it, and its test proves it refuses at the caps (`triage.test.ts`). Never log the text sent or the key.
- Townsfolk chatter spends money and writes as residents. Every call (scheduled turn or mention answer) goes through `reserve` in `src/chatter.ts`, which checks the key, the breaker, and the daily call, token, and dollar caps before it fetches, reserving `worstCostMicroUsd` and settling to the cost. Chatter never sends `fallbacks`, so no call costs more than it reserved, and `answer` checks the day again right before it acts. The model names a post or resident only by a ref from lists the service built; `checkAnswer`, a `Moderation` with no townsfolk privilege, and `createPost` check the words. A mention's words reach the model only inside the untrusted block. A giver's job words come from the board ([decision 0266](../../docs/knowledge/decisions/0266-a-giver-s-townsfolk-chatter-can-mention-the-day-s-job-in-the.md)). `chatter.test.ts` proves each cap and mention guard refuses. Never log the text sent, the text written, or the key.
- Every AI call writes a ledger row through `AiSpend.record()` (`src/ai-spend.ts`): purpose, trigger code, model, token counts, cost from `PRICES`, outcome. Never text or a resident id. A refused call writes none, and no guard reads the ledger. A new model needs a `PRICES` row first.
- Code names a model tier, never a model id. `MODELS` in `src/models.ts` maps `opus`, `sonnet`, and `haiku`, and `capabilitiesOf` says what each model takes, so a request never sends a field a model refuses. Moving a tier is its `MODELS` line, a capability row, and a `PRICES` row.
- Telemetry gets templates and codes. Spans, breadcrumbs, metrics, and reports go through `src/telemetry.ts` and carry route templates, route ids, status and error codes, and sim command types. Never an id, handle, token, key, code, IP, or resident text, even though the scrubber would catch most ([decision 0037](../../docs/knowledge/decisions/0037-server-error-reports-traces-and-breadcrumbs-carry-templates-.md)). Logs from the background runs (lessons, tips, welcomes, routines) carry counts and codes too. An error you catch and answer with `internal` also gets `report(err, where)`.

### Pictures

- Cards, plot photos, and pictures by link are drawn in the Worker, never in the World object. The World object calls the Worker's `PlotPhotos` entrypoint and its `picture` RPC answers with data only; the drawing happens in the cards Worker over the `CARDS` service binding ([decision 0299](../../docs/knowledge/decisions/0299-card-drawing-moves-to-a-worker-of-its-own-reached-over-a-ser.md)). Nothing here imports `@terrakin/cards/worker`, since its wasm would slow this Worker's every cold start. Build the `Card` here, call `env.CARDS.render`, and keep the caches and caps here.
- Public pictures cost CPU, so they're capped. A picture by link is asked of the world only past `allowPicture` (per IP), and drawn only with room in `allowRender` (per IP, looked at first, spent last) and `allowDraw` (all clients, per isolate or process); over any of them it gets the static card. `Cache-Status` says whether this answer drew it (`PICTURE_CACHE_STATUS`), made per answer and never cached. Nothing forces a draw past the caps. An unknown id is remembered `MISSING_TTL` seconds. Pictures show no uploaded art but a plot's home picture, only through `artShown`, so a purge changes the key. `pictures.test.ts` proves each cap and the art rule.
- `takePlotPhoto` runs the cost guards (the `photos` and `photosIp` limits, upload caps with room for a photo, per-IP bytes, two in flight) before drawing, and stores the PNG through `upload()`. `plot-photo.test.ts` proves each guard refuses before anything is drawn.

## Where things are

- `src/handlers/` route handlers, one `<area>Handlers(api)` per route table area. `handlers/shared.ts` has `fail`, `fromResult`, `ipKey`, `worldStaffId`. `handlers/safety.ts` holds the staff routes. `handlers/docs.ts` serves `SKILL.md` and its first-visit slice.
- `src/api.ts` the dispatcher (match, auth, rate limit, parse) and `Api`. `actWalk` walks a `move` with `steps` a tile at a time, a rate-limit token per tile after the first ([decision 0315](../../docs/knowledge/decisions/0315-a-move-takes-steps-walked-a-tile-at-a-time-and-paid-for-per-.md)). `src/api-response.ts` turns replies into HTTP, including the catalog's `ETag` and 304. `src/api-wiring.ts` connects world and social once at start (`wireSocial`).
- `src/live.ts` the `/v1/live` socket (`LiveSession`). Watch sockets are capped in all and per IPv6 /48 (`PostListeners`), closed after `WATCH_MAX_MS` or `WATCH_SILENT_MS` silent, and end on revocation; `announce` sends new post ids to everyone but those blocked either way with the author ([decision 0046](../../docs/knowledge/decisions/0046-new-posts-go-out-as-ids-on-the-live-socket-and-check-ins-ans.md)).
- `src/app.ts` the Node adapter; idle connections stay open `KEEP_ALIVE_MS`, longer than the proxies in front ([decision 0130](../../docs/knowledge/decisions/0130-the-node-server-keeps-idle-connections-open-for-65-seconds.md)). `src/main.ts` its entry point; every env var it reads is in [docs/deploy.md](../../docs/deploy.md). `TERRAKIN_TEST_CLOCK`, `TERRAKIN_TEST_X_OEMBED`, and `TERRAKIN_TEST_CHAIN` refuse to run with `NODE_ENV=production`, and the test routes they turn on that write (`maintainer`, `grant`, `open-land`, `open-plot-market`, `open-clay`) answer loopback callers only ([decision 0147](../../docs/knowledge/decisions/0147-test-residents-are-built-through-real-actions-with-a-test-on.md)).
- `cloudflare/worker.ts` the Worker and the `World` Durable Object ([decision 0012](../../docs/knowledge/decisions/0012-host-on-cloudflare-workers-with-one-durable-object.md)), config in the root `wrangler.jsonc` and `wrangler.cards.jsonc`. Each reads its deploy id from `CF_VERSION_METADATA` (`build` on `/v1/health`, `terrakin-worker-build` header); the two can differ for minutes after a deploy.
- `src/world-service.ts` the world: sessions, actions, presence, snapshots, and `tick()`. `src/world-actions.ts` checks and fills in actions before they're logged (`performAction`, `closedDoor`, `castRoll`). `src/world-wire.ts` what goes out (`toWire`, `eventsFor`, `holdBackNames`, `worldSnapshot`). `src/world-credentials.ts` tokens and link keys, hashes only.
- Names: `createResident` refuses the sim's `nameProblem` and a name taken by `nameKey` (`src/text.ts`), offering `freeNames` ([decision 0379](../../docs/knowledge/decisions/0379-a-resident-s-name-is-ascii-letters-digits-and-underscores-ch.md), [decision 0148](../../docs/knowledge/decisions/0148-resident-names-are-unique-at-join.md)); maintainers rename with `renameResident`.
- `src/repeat-joins.ts` retiring unused repeat joins (Worker only, [decision 0230](../../docs/knowledge/decisions/0230-old-repeat-joins-are-retired-once-by-a-logged-input-the-sim-.md)) and merging a used duplicate ([decision 0239](../../docs/knowledge/decisions/0239-a-duplicate-record-is-merged-into-the-record-that-stays-by-a.md)). Any call ever made, and a bound passkey, count as use. Retired and merged records keep their credentials as retired, so a failed call says why; moderation rows stay.
- Presence: with `presence`, REST and link callers `arrive()`, which only notes them unless the action is `chat` ([decision 0071](../../docs/knowledge/decisions/0071-presence-comes-with-acting-once-implicit-presence-is-logged.md)). `putter` ([decision 0049](../../docs/knowledge/decisions/0049-putter-is-a-planned-short-walk-logged-as-its-steps-with-a-on.md)) and `build` (`BUILD_LIMITS`, in memory, dry runs don't count) have their limits here, answered as `rate_limited` with `retryAfter`. `build` and `add_floor` answer with what the sim's `prepare` hands back, so a dry run prices and plans and spends nothing (`build.test.ts`). `facing` and `routine` are in memory only.
- `src/store.ts` `MemoryStore` and `JsonlStore`; sessions are append-only. `src/sql-store.ts` Durable Object SQLite, with transactions through `ctx.storage.transactionSync`, since a Durable Object refuses `BEGIN`. `src/node-sql.ts` `node:sqlite` in the same shape.
- `src/snapshots.ts` world snapshots ([RFC 0014](../../docs/rfcs/0014-world-snapshots.md), [decision 0069](../../docs/knowledge/decisions/0069-the-world-boots-from-a-verified-snapshot-and-the-log-after-i.md)) and the boot. The body is `JSON.stringify`, never `canonicalJson`. A snapshot is booted from only once verified, with a known `format`, the sim's `REPLAY_VERSION`, and matching SHA-256, `seq`, hash, and coin supply; else the boot falls back. Reports carry codes and `seq`s only, through `reportable`. A snapshot by hand is refused while another waits to be verified.
- The world-log export (`GET /v1/admin/world-log`, `logPage`) holds residents' words: maintainers and the deploy token only, an Access sign-in on terrakin.org, capped pages, never cached, and a bad row reported by its kind alone.
- `src/social-service.ts` posts, handles, reactions, follows, blocks, profiles, uploads and their caps, and notifications. Every notification from a resident goes through `notify()`; one from Terrakin through `systemNotice` or `takedownNotice()`. Its tables never feed the sim.
- `src/praise.ts` praise and `src/pets.ts` pats: once a UTC day per pair, daily caps, never across a block. Pet and plot names are filtered (`pet_name`, `plot_name`) before they're logged.
- `src/plots.ts` plot views, admires, and visits ([decision 0092](../../docs/knowledge/decisions/0092-admiring-a-plot-is-a-social-row-from-on-or-beside-it-once-a-.md)). A plot's name ([decision 0121](../../docs/knowledge/decisions/0121-a-plot-s-name-lives-on-the-plot-in-the-sim-set-by-its-reside.md)) is shown through `shownPlotName`, which holds it back while its writer's words are held. `visit` fills in `visitTile` ([decision 0091](../../docs/knowledge/decisions/0091-visit-is-a-jump-to-a-neighbor-s-door-logged-with-the-tile-th.md)).
- `src/plot-news.ts` a plot's one news line from counts, never text (decision 0307, [decision 0337](../../docs/knowledge/decisions/0337-a-roof-can-wear-a-vane-a-flag-or-a-nest-on-its-ridge.md)).

## Testing

`src/server.test.ts` starts a real server on port 0 and talks to it over `fetch` and `ws`. Every new route or message type gets an integration test. Use `MemoryStore` unless you're testing persistence. Pass `onResponse` from `responseChecker()` (`src/test-support.ts`) to every test server; it fails the suite on a response that doesn't match the route table. Use `listenOnFreePort` (127.0.0.1 only, never every address) and `jsonCaller` from there instead of writing another.

The server project runs with `isolate: false` (`vitest.config.ts`): a test file never swaps a module with `vi.mock` and puts back any global it changes. To see what `report` and `gauge` send, use `recordTelemetry()` from `src/test-support.ts`, with `start` before each test and `stop` after.

## Writing tests

A test here answers the four questions in the root [definition of done](../../AGENTS.md#definition-of-done) first. A near-copy here usually means a second server: extend the test that owns the contract instead.

The HTTP route test owns a route's contract. A unit test of a helper behind the route earns its place only with cases the route can't reach cheaply. Every cap that guards money keeps a test that fails when the cap is bypassed. Resident text in a test never holds a random id: the filters fold leetspeak, so an id holding `a55` reads as strong language and the test fails now and then.
