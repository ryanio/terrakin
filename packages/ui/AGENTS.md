# packages/ui/

`@terrakin/ui`: the browser pieces the app (`packages/client/`) and the staff app (`packages/admin/`) share. It has no build of its own; each app's Vite build bundles what it imports (`@terrakin/ui/dom`, `@terrakin/ui/tokens.css`, ...). Why the components live here: [decision 0041](../../docs/knowledge/decisions/0041-shared-ui-components-live-in-ui-with-their-styles-and-a-test.md).

## Rules

- **Build it once, here.** If a view needs something another view already draws (an avatar, a name with badges, a time, a state card, an empty note, a sheet, a checkbox row, a link to a profile or post), use the function below. If a piece shows up in a second place, move it here first. `packages/client/src/shared-components.test.ts` fails on the hand-built versions it knows about; add a pattern there when you add a component.
- **Every size comes from a scale.** Gaps, padding and margins of 4px or more are `--space-*`, font sizes `--text-*` (or a `clamp()` headline), corners `--r-*`, line heights `--leading-*`, weights `--weight-*`, all in `src/tokens.css`. Under 4px is a hairline or a nudge; geometry tied to a fixed size goes in a `calc()` that says what it measures. The same test checks every stylesheet.
- **Two page layouts.** A page is a `.column` (one centered column, `--page-narrow`) or a `.layout` (`--page-wide`). Build a `.layout` with `pageLayout(className, sideLabel)` in `ui.ts`, which gives a head over the main column and a 360px sidebar beside them from 1000px, or `wideLayout(className)` for a page of cards with no sidebar, whose main column takes the whole width (put the cards in a `.card-grid`). Below 1000px a `.layout` is one column: head, sidebar, main, or head, main, sidebar with `{ sideLast: true }` when the main column is what someone came for. Use a `.layout` for any page with something worth putting beside its main content (a balance, a form, a calendar, a ladder, who wrote it), and a `.column` for a form, a list read top to bottom, or a single thing. `.slot` keeps a place in the sidebar for a card that loads late. App stylesheets never set a page width or a sidebar grid of their own, and views never hand-build the layout's regions; tests fail on either.
- **Lay out with the primitives.** `stack` (a column, `.tight`, `.cards`, `.start`), `cluster` (a wrapping row) and `plain-list` go in a view's class list next to its own class (`stack paper card things-card`). Don't restate them in an app stylesheet; a test fails on a rule that does. A view's body inside `.page` is a `stack cards`, so its cards never touch, and a `.section-title` gets the room above it from the page, not from its own margin.
- **A component's styles live in `src/base.css`.** Never in `packages/client/src/style.css` or `packages/admin/src/style.css`, which may add contextual rules (`.claim-agent .person-name`) but never redefine a base selector. The same test checks this, and that no stylesheet defines a selector twice.
- **Resident text is text.** `h()` in `src/dom.ts` puts strings in as text nodes, and `mentions.ts` turns text into text nodes and links, never HTML. Nothing here uses `innerHTML` or `insertAdjacentHTML`.
- **Works under both apps' policies.** The staff app allows no inline script or style and no `data:` fonts, so nothing here injects a `<style>`, sets a `style` attribute from markup, or loads from another host. Setting styles through the CSSOM (`el.style.setProperty`, `el.style.aspectRatio`) is fine; a policy only blocks style attributes in markup and inline `<style>`.
- **No app state.** No tokens, storage, routes, or telemetry here. Pass them in, like `makeRequest({ headers, onError, breadcrumb, onBadResponse })` in `src/http.ts`.
- **Only our media.** Anything that takes a media URL checks it with `isMediaUrl` (`src/format.ts`).
- **Plain words, shared.** `src/safety.ts` holds the labels for report reasons, triage categories, and moderation actions, and `RULE_WORDS` (the rule a takedown notice cites), so the Report sheet, takedown notices, and the staff queue say the same thing.
- **Tests live with the apps** that use these pieces (`packages/client/src/*.test.ts`, `packages/admin/src/logic.test.ts`), so a change here runs both apps' tests through `pnpm verify`.

## Writing tests

A test for a piece here lives in the app test that uses it (the last rule above) and passes the same four questions `packages/client/AGENTS.md` asks: what behavior it protects, what regression makes it fail, why an existing test doesn't catch that already, and whether it needs an export no production code uses (then test the real caller instead). Test at the lowest level that catches the bug, as the root `AGENTS.md` says. A test that copies a token list, restates a lookup table such as `REACTIONS`, or checks a helper against its own output protects nothing.

## Where things are

- `src/tokens.css` design tokens on `:root`: colors, the spacing, type and corner scales, and the page rhythm (`--gap-page`, `--gap-section-head`). `src/base.css` resets, the layout primitives (`.stack`, `.cluster`, `.plain-list`), the page layouts (`.column`, `.layout`, `.slot`, `.card-grid`), the shared pieces (`.paper`, `.card`, `.section-title`, `.pill`, `.pill-button`, `.btn-primary`, `.avatar`, `.icon`, `.hint` for a muted line in the size of the text around it, ...), and the styles of every component below.
- `src/people.ts` `avatarEl`, `paintAvatar` (repaints in place; a figure from its look paints once `figure.ts` arrives, which `people.ts` starts loading with `import()` when it runs, so the drawing stays out of the first load, [decision 0231](../../docs/knowledge/decisions/0231-the-client-build-leaves-out-zod-s-json-schema-code-and-draws.md); `hasLook` in `src/looks.ts` says whether there is one), `avatarPlaceholder`, `avatarStack` (a few faces in a row, each tucked under the last: who sits at a game table, who a live notice is about), `badges`, `personLink` (avatar, name, and badges as one link; `picture: false` draws only an initial and `picture: "drawn"` their figure without anything they uploaded), `personLabel` (the same avatar and name as text, for where a link would go nowhere: who's signed in to the staff app), `partnerMark` and `flairChip` (RFC 0007; `badges` adds the flair and `avatarEl` the partner's ring, `.ring-<border>` in `base.css` for each of `PARTNER_BORDERS`), `residentPerson`, `who`, `tagCard` (a tag, a few words and a person on one line in a small card), `ownerLine` ("AI of <owner>" as a `tagCard`; `badges(who, false)` leaves out the bare "AI" beside it), `keeperCards` ("Keeper of <character>" as a `tagCard` for each partner character a person owns, RFC 0007; bylines show the first), `xMark`, quote embeds.
- `src/tooltip.ts` `tip(el, text)`: a few words in a small dark bubble that fades in over a label to say what it means (the "AI" and "Townsfolk" pills, partner marks, karma). A mouse resting on the label shows it; on a phone a tap does, unless the label sits in a link or button. One bubble serves the page; it and its listeners live in `src/tooltip-bubble.ts`, loaded the first time a label gets a tooltip so they stay out of the first load, and placed by the pure `tipPlace`. Screen readers get the words as the label's `aria-description`. Use it instead of a `title` on a label that explains itself, and never with `cursor: help`.
- `src/skeleton.ts` loading placeholders: `skeletonPage(shape)` (a whole page of them in the real page's layout: a sidebar layout, a wide grid, or a column, holding posts, a list of rows, cards, a grid of cards with a picture each, or one card, under a title bar, a profile header, a card, or nothing), `skeletonPosts`, `skeletonCard` (a heading line and a few lines, taking the classes of the card it stands in for), `skeletonTiles` (cards with a square picture each, for a card grid), and `skLine`. A placeholder or a page of them fades in after a short wait, so a quick load never flashes one; the shapes breathe faintly in `--paper-edge` and hold still under reduced motion (`.sk`, `.skeleton`, and `.skeleton-page` in `base.css`). Every placeholder is built from these; add a shape here rather than in a view.
- `src/when.ts` `timeAgo` (a `<time>` with the full date on hover) and `refreshTimes`.
- `src/ui.ts` `itemRow` and `itemRows` (a picture, a name with a line or two under it, and an amount or a button: the purse ledger, your things, the shop's buy orders, a workshop's choices), `progressBar` (a thin moss bar for how far along something is, a `progressbar` for screen readers: the collection book, Getting started, the skills sheet), `kindPill` (a small tinted label for what kind of thing a card or row is, moss or sun, shown as written: a proposal's kind, who put up a bounty, the shop's "This autumn"), `linkTabs` (a switch between sibling pages, links with the current one `aria-current="page"`: plots and galleries, someone's followers, following, and friends; or with `pick`, between panels on one page, buttons in a tablist with the current one `aria-selected`, the arrow keys moving between them, and `pickTab` to mark one from outside the row: the feed's Everyone and Following, the build bar's Blocks, Paths, and Furniture, the games' four ladders), `stateCard`, `emptyNote`, `errorLine`, `checkRow`, `chips`, `closeButton` (a round X named for screen readers: a sheet's close, or putting a card away) and `cardBar` (a card's eyebrow with a `closeButton` on one line: the devlog and Getting started cards), `sheet` (a bottom sheet on a phone, with a grab bar and a pull down that closes it unless something is typed in it, and a centered card from 640px; its `card` takes focus with no ring, for a sheet whose buttons are all choices, so none opens looking picked), `moreMenu`, `dropdown`, `disclosure`, `moreButton`, `whileBusy`, `whileBusyAll` (a card's buttons all off with a "Saving…" line, back on with the reason when it fails: the staff queue and bounties), `holdFocus`, `confirmTwice`, `copyButton`, `copyBlock`, `announce`, toast, overlay, popover, `shareLink`, and `shareOnX` (X's post box with the words and a page's link; X's link can't carry a picture, so a picture goes to a phone's share sheet, or is copied for pasting anywhere else). The overlay owns one history entry: `closeOverlay(dialog)` closes only that dialog, and the router calls `leaveOverlay` before every navigation so the new page replaces the overlay's entry. Closing one plays its `.closing` animation from `base.css` before it leaves the page, except when the page is changing under it.
- `src/toast.ts` (the toast) and `src/copy.ts` (`copyBlock`, `copyButton`, `copyText`, `announce`) need nothing but the DOM helpers, so a page without the app can load them alone: the docs pages' one script does ([decision 0211](../../docs/knowledge/decisions/0211-the-docs-pages-load-one-small-script-of-their-own-for-copy-b.md)). `ui.ts` re-exports both; import them from there in the apps, and keep both modules free of the protocol.
- `src/brand.ts` `BRAND_HEX`: the token colors as hex, for canvas and WebGL. `src/poll.ts` `visiblePoll` (throttled refresh while the tab is visible) and `everyVisible`.
- `src/motion.ts` `reducedMotion`, `REDUCED_MOTION`, `replay`, `countTo`, `showNumber`.
- `src/paths.ts` `profilePath`, `postPath`, `plot3dPath`, `collectionPath`: every link to a resident or a post.
- `src/dom.ts` `h()` and `icon(name)`. `src/icons.ts` maps each icon name to a [Lucide](https://lucide.dev) glyph; every icon on the site comes from there. Need a new one? Add a line to the map with the Lucide icon that fits. Never draw one by hand. index.html writes `<svg class="icon" data-icon="name" aria-hidden="true"></svg>` and the client build fills it in from the same map.
- `src/http.ts` the typed request helper: every response parsed with a protocol schema, and a 401 told in the app's own words (`unauthorized`), never the server's.
- `src/format.ts` pure helpers (times, `shortDate` for "Oct 6" with the year when it isn't this one, counts, `formatCount` for "1,234", `plural`, `pluralWord` for the word alone beside a count shown apart, `badgeText`, the media grid, `isMediaUrl`). `src/media.ts` post media, the lazy model viewer hook, and `usePlaceTap`, how the app's "Jump there" reaches a picture with a `place`. `src/mentions.ts` mention links and web addresses in post text, drawn by `src/links.ts`: `findLinks` (http and https only, no login before the host), `linkLabel` (the host and as much of the rest as fits in 32 characters), and `linkHref` (our own pages directly, anywhere else through `/away`). `src/looks.ts` and `src/figure.ts` themes and the drawn figure, whose face shows a feeling from `src/feelings.ts` (`FEELINGS`, the fixed list), a blink and a raised hand, and an umbrella rolled up (`furled`, the world's dry weather; pages show it open), with `drawFeelingIcon` for the sign that floats over it, on a paper disc (or a crescent `moon` beside someone away and out on a routine), and `signPx` for its size on the map. Every garment has its own path builder and paint function, and `paintCloth` fills it with its color and clips its pattern into it, the same way the clothes get theirs. `garmentLook` (pure) works out a garment's color and pattern from the look and its `wearStyle`. Hair (`hairOf` in `src/looks.ts`, pure, and `hairParts`) is drawn in two layers, behind the body and on the head after the face, with its own shapes for each facing; a hat that covers the crown (`HAT_COVER`) is drawn over it and clips what's under its band ([decision 0074](../../docs/knowledge/decisions/0074-hair-is-a-style-and-a-color-on-the-look-drawn-under-hats-in-.md)). `hairName` in `src/looks.ts` says it in words ("Auburn bob"). Halloween's costumes (RFC 0022) draw from every facing too: a witch hat over the hair with its band, cat ears on the head, bat wings behind the body, and a pumpkin head or a ghost sheet that hides the hair (`hidesHair`). Their colors are `HALLOWEEN_HEX`, and `BAT_POINTS` (one bat for bunting and pictures) and `BAT_WING` (a worn wing) are shared with the map and the 3D views. Winter's decor and sweets (RFC 0017) take their colors from `WINTER_HEX` the same way: the snowman's snow and its cool shade, the bulbs of a string of lights, the fir's needles and pot, the sled's runners and slats. Earned wear (RFC 0029) takes its colors from `EARNED_HEX`, shared with the item pictures and the 3D figures: a wide sun hat over the hair (a `HAT_COVER` hat), a field vest open at the front, a party sash across the chest and a tool belt at the waist (both inside the body's clip, the belt's pouch and hammer over it), and a rosette pinned to the chest, which a turned back hides.
- `src/figure-svg.ts` the same figure for pictures drawn away from a browser ([decision 0160](../../docs/knowledge/decisions/0160-pictures-by-link-are-public-cached-pngs-of-a-plot-a-look-and.md)): `figureDrawing(look, facing)` runs `drawFigure` into `SvgPen`, a stand-in canvas that keeps fills, strokes, clips, and pattern tiles as SVG path data, for the server's pictures by link. A look there never has `patternMedia`. `src/figure-drawing.ts` is its DOM-free signature, which `package.json` gives as the types of `@terrakin/ui/figure-svg`, so the server typechecks without the DOM; keep the two in step.
- `src/item-art.ts` `thingPicture(thing, opts)` (a piece's own uploaded picture, else the drawn one), `piecePictureUrl(thing)` (that picture's URL alone, for the 3D views), `itemArtImage(kind)` (the drawn picture as an image, for the world's canvas) and `itemArtLoaded(kind)` (the same once it has loaded, for a texture), and `itemArt(kind, { title?, size?, className? })`: a drawn SVG of any item or piece of wear, built with `createElementNS` from the pure `itemShapes`. Produce, seed packets, and jars are drawn from each kind's look in the sim's catalog (RFC 0018): produce from its outline (`SHAPES`), what grows on top (`TOPS`), and its colors, a packet from the crop it grows, a jar from its fill, its cloth or lid, and the kind on its label. Everything with a `drawn` look (the pantry's staples, materials, decor, furniture, made goods with no template, the finds of RFC 0021, Halloween's candy and decor, winter's hot cranberry punch, decor, and candy canes, and the fishing rod, fried minnows, and fish stew of RFC 0023) has its own drawing in `DRAWN`, and wear in `WEAR_ART`, the costumes and the five earned garments included. A recipe page lying on the ground (RFC 0024) isn't a thing you hold, but `recipe_page` is an `ArtKind` too, a small scroll (`recipePage`), so the map and the 3D world draw it like a find. Fish are drawn from their `fish` look (RFC 0023): a body frame for each shape in `FISH_FRAMES` (slim, deep, and long; a small fish is the slim one scaled down, and an eel a curve of its own) in the look's colors, with its spots, bars, band, scales, or whiskers, each part its own group, so a silhouette tells one fish from another. `CROP_HEX` (each ripe crop's color, its look's `body`), `onVine` (whether a crop grows along the soil), and `growth` (how far along a crop is) come from the sim's palette and are passed on here, so the world map, the 3D views, and the plot photos draw crops alike. Styles: `.item-art` in `base.css`.
- `src/ground-art.ts` paths and floors (RFC 0016) from the sim's `GROUND_LOOK`: `paintGround` draws a tile on a canvas (the world map, and the 3D views' ground texture) and `groundArt(kind)` a swatch as an SVG (the build bar). Styles: `.ground-art` in `base.css`.
- `src/pet-art.ts` `petArt(kind, coat, opts)` (a pet as an SVG, awake or asleep, with an open or happy face, for the Adopt sheet, pet cards, and the pet sheets) and `drawPet` (the same shapes painted on a canvas, for the map's sprites), both from the sim's `petShapes` ([RFC 0019](../../docs/rfcs/0019-pets.md)).
- `src/safety.ts` trust and safety labels.
- `src/reactions.ts` `REACTIONS`, the emoji and name for each reaction key, for the client's posts and the staff app's townsfolk page.
