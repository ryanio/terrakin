# scripts/

Repo tooling. Plain Node with type stripping, so it runs right after `pnpm install` with no build step. Each script's header comment lists its flags, outputs and exit codes; read it before you run or change one.

| Script | Command | What |
|--------|---------|------|
| `gen.ts` | `pnpm gen`, `pnpm gen:check` | Writes everything derived from the route table, site config, `CHANGELOG.md` and `docs/devlog`. The header lists every output. |
| `kb.ts` | `pnpm kb`, `pnpm kb new <kind> "Title"` | Rebuilds `docs/knowledge/INDEX.md` and creates entries. A new decision is numbered past the newest on `origin/main`; `--check` fails when two decisions or two RFCs share a number. |
| `economy-sim.ts` | `node scripts/economy-sim.ts [flags]` | Plays a month of residents, gardens and the town shop through the real sim and prints the coin numbers and each system's checks. Flags are in its header. |
| `coin-flow.ts` | (used by `economy-sim.ts`) | The choices behind the sim's coin-flow flags, pure and tested ([decision 0278](../docs/knowledge/decisions/0278-coin-flow-the-townsfolk-welcome-tip-rises-to-25-and-jobs-sti.md)). |
| `replay-bench.ts` | `node scripts/replay-bench.ts [--inputs ...] [--planner]` | Measures what a cold start pays to replay a synthetic log, and what a snapshot costs ([RFC 0014](../docs/rfcs/0014-world-snapshots.md)). |
| `brand/` | `pnpm brand` | Draws the logo, favicons, app icons, social card and X header from one config ([README](brand/README.md)). |
| `townsfolk/` | `pnpm townsfolk`, `pnpm townsfolk:avatars`, `pnpm townsfolk:tips` | Seeds the founding townsfolk through the public API and sets their handles, routines, pets, roofs, avatars and tips ([README](townsfolk/README.md)). |
| `sentry.ts` | `node scripts/sentry.ts issues \| issue <id> \| trace <id> \| resolve <id>` | Reads production errors and traces from Sentry, and resolves an issue once its fix is live ([decision 0037](../docs/knowledge/decisions/0037-server-error-reports-traces-and-breadcrumbs-carry-templates-.md)). |
| `deploy.ts` | `pnpm cf:deploy` | Deploys both Workers from the tip of `origin/main`, cards Worker first, after `replay-check.ts` passes ([decision 0299](../docs/knowledge/decisions/0299-card-drawing-moves-to-a-worker-of-its-own-reached-over-a-ser.md), [docs/deploy.md](../docs/deploy.md)). |
| `deploy-smoke.ts` | `node scripts/deploy-smoke.ts [--base ...] [--version <id>] ...` (CI's `smoke` job) | Asks the live Worker for what the suite can't see from Node: health, the world's switches, drawn pictures, file types, the homepage script ([decisions 0250](../docs/knowledge/decisions/0250-a-smoke-check-asks-the-live-worker-for-drawn-pictures-after-.md), [0263](../docs/knowledge/decisions/0263-the-smoke-check-waits-for-the-world-object-to-run-the-deploy.md), [docs/deploy.md](../docs/deploy.md#the-smoke-check-after-a-deploy)). |
| `replay-check.ts` | `node scripts/replay-check.ts [--base https://admin.terrakin.org]` | Replays the live world's log under this checkout's sim and checks the hashes ([RFC 0014](../docs/rfcs/0014-world-snapshots.md), [decisions 0070](../docs/knowledge/decisions/0070-replay-version-marks-rule-changes-that-make-old-snapshots-un.md), [0257](../docs/knowledge/decisions/0257-ci-s-deploy-signs-in-for-the-replay-check-with-an-access-ser.md)). |
| `landlocked.ts` | `node --import ./scripts/resolve-ts.mjs scripts/landlocked.ts [--out landlocked.md]` (nightly) | Lists claimed plots with no way out, with the sim's `landlockedFrom` ([decision 0351](../docs/knowledge/decisions/0351-a-plot-s-way-out-is-a-step-from-its-hearth-s-walk-onto-groun.md)). |
| `ways.ts` | `node --import ./scripts/resolve-ts.mjs scripts/ways.ts [--keep-free] [--json]` | Dry run of downtown's public way plan with the server's `planWays` ([RFC 0046](../docs/rfcs/0046-streets.md)). Laying a plan is the staff route `POST /v1/admin/ways`. |
| `e2e-needed.ts` | `node scripts/e2e-needed.ts` (CI's `changes` job) | Prints whether this CI run needs e2e ([decision 0200](../docs/knowledge/decisions/0200-e2e-keeps-only-journeys-a-lower-test-can-t-prove-with-a-budg.md)). |
| `first-load.ts` | `node scripts/first-load.ts [--top 40]` | Prints what the client's first load holds against `FIRST_LOAD_BUDGET` ([decision 0258](../docs/knowledge/decisions/0258-the-first-load-s-budget-is-135-kb-counted-as-it-is-downloade.md)). Run it before and after a change to the first load. |
| `persona.ts` | `pnpm persona [stage] [--open-clay] [--open-plot-market] [--job id] ...` | Makes a resident at a stage on the `pnpm dev:test` world and prints the line that signs a tab in as them. Stages are `e2e/personas.ts` ([decision 0147](../docs/knowledge/decisions/0147-test-residents-are-built-through-real-actions-with-a-test-on.md)). The test world's clock moves with `POST /v1/test/advance-day?days=1` or `?minutes=75`. |
| `funnel.ts` | `pnpm funnel [--save f.json] [--since f.json]` | Prints the newcomer funnel from `GET /v1/admin/newcomers` as Markdown, in the staff app's step names. Signs in with `TERRAKIN_STAFF_KEY` through the secrets wrapper. |
| `devlog-shot.ts` | `pnpm devlog:shot <name> [--persona settled] [--path /world] ...` | Takes a phone screenshot for a devlog post from the `pnpm dev:test` world and prints its Markdown line. |
| `docker/` | | The container entrypoint. |

## Rules

- Rerun `economy-sim.ts` before changing a number in `ECONOMY`, the pantry, the shop, a season, `RECIPES_RULES`, `FLOORS`, `PROGRESS` or `JOBS` (try one first with `--set key=value`), and record why in a decision ([0039](../docs/knowledge/decisions/0039-phase-1-coin-numbers-tuned-with-a-simulated-month.md), [0052](../docs/knowledge/decisions/0052-the-town-shop-sells-decor-and-wear-buys-a-rotating-few-goods.md), [0079](../docs/knowledge/decisions/0079-autumn-s-numbers-pumpkins-pumpkin-pie-and-soup-hay-bales-and.md), [0124](../docs/knowledge/decisions/0124-winter-s-numbers-cranberries-hot-cranberry-punch-winter-deco.md), [0186](../docs/knowledge/decisions/0186-recipes-keep-the-rfc-s-card-prices-and-page-rate-the-economy.md), [0210](../docs/knowledge/decisions/0210-halloween-s-costumes-and-decor-cost-half-from-a-logged-lower.md), [0242](../docs/knowledge/decisions/0242-a-storey-costs-200-coins-the-economy-run-with-builders-says-.md), [0246](../docs/knowledge/decisions/0246-level-n-to-n-1-takes-20-points-times-n-a-lesson-and-a-counte.md), [0255](../docs/knowledge/decisions/0255-a-job-pays-10-points-and-three-count-a-week-the-economy-run-.md)).
- A new system in `economy-sim.ts` draws from its own PRNG stream and gets a `--no-` flag (or an opt-in flag) that draws none of it, so the month without it plays exactly as before.
- `deploy.ts` refuses an older or dirty HEAD and refuses when the replay check fails. Never work around it: a Worker older than the live one can't replay the log and takes the world down.
- `deploy-smoke.ts` only reads. A check that needs a token, a resident, or a write doesn't go in it, and a new picture check keeps the run under the per-address draw caps in [packages/server/AGENTS.md](../packages/server/AGENTS.md). Every switch the Worker sets has a row in `SNAPSHOT_FIELDS` (a test fails otherwise).
- `replay-check.ts` never prints an input, an error that could quote one, or writes one to disk: the log holds residents' words. A staff token goes only to a server on this machine, and no script sends a sign-in or staff key over plain http to another host.
- `landlocked.ts` and `ways.ts` name plots by coordinates and owners by id, never anything a resident wrote.
- `persona.ts` and `devlog-shot.ts` talk only to a server on this machine.
- `e2e-needed.ts` skips e2e only when every changed file is one no page or server is built from; when it can't tell, e2e runs.
- A script that reaches a workspace package through a plain `import` runs as `node --import ./scripts/resolve-ts.mjs <script>` (the three `townsfolk` ones do), since the packages import each other without file extensions and Node resolves a script's whole import graph before it runs a line of it. A script that reaches them with `await import(...)` registers the same hook itself, as `gen.ts` and `economy-sim.ts` do.
- Generators are deterministic: rerunning with no input change writes identical files. Check mode compares content or hashes, never dates.
- Never hand-edit generated output. Change the source and rerun.
- `pnpm townsfolk` against `https://terrakin.org` writes to production. Do a `--dry-run` first, and treat it as the owner's call.
- `pnpm townsfolk -- --handles`, `--routines --pets --roofs`, `pnpm townsfolk:avatars` and `pnpm townsfolk:tips` are dry runs unless you pass `--send`. With `--send` against `https://terrakin.org` they change the live world (tips give real coins): the owner's call. Their plans (`handle-plan.ts`, `routine-plan.ts`, `pet-plan.ts`, `roof-plan.ts`, `avatar-plan.ts`) are pure and tested. It never adopts a second pet, and every roof is a free covering that gives the old one back ([decision 0330](../docs/knowledge/decisions/0330-the-townsfolk-s-homes-wear-roofs-in-the-free-coverings-and-n.md)).
- The tip choosing logic lives in `packages/server/src/tip-plan.ts`, pure and tested, shared with the server's daily run (`packages/server/src/townsfolk-tips.ts`); keep the network and files in `tips.ts`.
- Each persona's `specialties` (the recipes the server's lessons run has it teach, RFC 0024) live in `packages/server/src/lesson-plan.ts`, which `personas.ts` reads. Nothing here sends them.
