# scripts/

Repo tooling. Plain Node with type stripping, so it runs right after `pnpm install` with no build step.

| Script | Command | What |
|--------|---------|------|
| `gen.ts` | `pnpm gen`, `pnpm gen:check` | Writes everything derived from the route table and site config: the API blocks in `SKILL.md` and `llms.txt`, `openapi.json`, discovery files, docs guides, `docs/site/lastmod.json`, everything built from `CHANGELOG.md` (with the API fingerprint check), and everything built from the posts in `docs/devlog`. The file header lists every output. |
| `kb.ts` | `pnpm kb`, `pnpm kb new <kind> "Title"` | Rebuilds `docs/knowledge/INDEX.md` and creates decision, learning, and handoff entries. A new decision is numbered past the newest on `origin/main`, and `--check` fails when two decisions or two RFCs share a number. |
| `economy-sim.ts` | `node scripts/economy-sim.ts [--start 2024-10-04] [--no-shop] [--no-fishing] [--no-recipes] [--picks sell] [--no-holidays] [--holiday-prices before] [--set key=value]` | Plays a month of residents, their gardens, and the town shop through the real sim, and prints supply per active resident, what the town paid, and what residents spent. The default month is in autumn, so it has autumn's stock and buying in it; `--start` plays another season (`--start 2024-12-04` is a winter month). Some residents fish (RFC 0023), from their own PRNG stream, so `--no-fishing` plays the month exactly as it was before fishing. A season's wishes are skipped in other seasons without a draw, so adding one leaves the other seasons' months as they were. Recipes are learned by default (RFC 0024): free picks, cards, lessons from neighbors and townsfolk, and recipe pages, from their own PRNG stream, so `--no-recipes` plays the month as it was before them; it also prints how many days newcomers take to a first sale and to knowing what they sell. Residents keep Halloween by default (RFC 0022): some want a costume and a piece of its decor and buy them while it runs, from their own PRNG stream, so `--no-holidays` plays the month as it was before; the world logs `lower_holiday_prices` as terrakin.org does, and `--holiday-prices before` plays decision 0107's prices. It prints what newcomers had to spend in their first week, who bought a costume and decor, and what holiday stock burned. Rerun it before changing a number in `ECONOMY`, the pantry, the shop, a season, or `RECIPES_RULES` ([decisions 0039](../docs/knowledge/decisions/0039-phase-1-coin-numbers-tuned-with-a-simulated-month.md), [0052](../docs/knowledge/decisions/0052-the-town-shop-sells-decor-and-wear-buys-a-rotating-few-goods.md), [0079](../docs/knowledge/decisions/0079-autumn-s-numbers-pumpkins-pumpkin-pie-and-soup-hay-bales-and.md), [0124](../docs/knowledge/decisions/0124-winter-s-numbers-cranberries-hot-cranberry-punch-winter-deco.md), [0186](../docs/knowledge/decisions/0186-recipes-keep-the-rfc-s-card-prices-and-page-rate-the-economy.md), and [0210](../docs/knowledge/decisions/0210-halloween-s-costumes-and-decor-cost-half-from-a-logged-lower.md)). |
| `replay-bench.ts` | `node scripts/replay-bench.ts [--inputs 100000,1000000,5000000] [--planner]` | Builds a synthetic log of scheduled agent check-ins through the real sim and measures what a cold start pays to load, parse, and replay it (time and heap), and what a snapshot of the result would cost to write, load, and verify ([RFC 0014](../docs/rfcs/0014-world-snapshots.md)). |
| `brand/` | `pnpm brand` | Draws the logo, favicons, app icons, social card, and the X header from one config. See its [README](brand/README.md). |
| `townsfolk/` | `pnpm townsfolk -- --base <url>`, `pnpm townsfolk -- --base <url> --handles [--send]`, `pnpm townsfolk -- --base <url> --routines --pets [--send]`, `pnpm townsfolk:tips -- --base <url> [--send]` | Seeds the founding townsfolk through the public API, claims their handles, sets their routines and adopts their pets, and spends their daily coin budgets on newcomers and the day's best post. See its [README](townsfolk/README.md). |
| `sentry.ts` | `node scripts/sentry.ts issues \| issue <id> \| trace <id> \| resolve <id>` | Reads production errors, their breadcrumbs, and traces from Sentry, and resolves an issue once its fix is live ([decision 0037](../docs/knowledge/decisions/0037-server-error-reports-traces-and-breadcrumbs-carry-templates-.md)). |
| `deploy.ts` | `pnpm cf:deploy` | Runs `wrangler deploy` only from the tip of `origin/main` with a clean tree. An older Worker can't replay a log the newer one wrote, so a stale deploy takes the world down ([docs/deploy.md](../docs/deploy.md)). In CI a superseded commit skips, unless every newer commit is `[skip ci]`. Before uploading it runs `replay-check.ts` and refuses when it fails. |
| `e2e-needed.ts` | `node scripts/e2e-needed.ts` (CI's `changes` job) | Prints `e2e=true` or `e2e=false`: whether this CI run needs e2e. It compares with the newest green run on `main` that HEAD contains (on a pull request, with its base) and skips only when every changed file is in `packages/sim/`, `scripts/`, `docs/`, or a `.md` file, and none is Markdown the client is built from or the server serves (`docs/site/`, `docs/devlog/`, `docs/guides/`, `packages/protocol/SKILL.md`, `packages/client/src/` and `public/`). A sim-only push skipping e2e is a trade-off: its unit tests own the rules, and the nightly 2D run catches a sim change that breaks a spec. When it can't tell, e2e runs ([decision 0200](../docs/knowledge/decisions/0200-e2e-keeps-only-journeys-a-lower-test-can-t-prove-with-a-budg.md)). |
| `replay-check.ts` | `node scripts/replay-check.ts [--base https://admin.terrakin.org]` | Pages through the live world's log (`GET /v1/admin/world-log`, maintainers only) and replays it under this checkout's sim, checking the live hash and the newest verified snapshot's ([RFC 0014](../docs/rfcs/0014-world-snapshots.md), [decision 0070](../docs/knowledge/decisions/0070-replay-version-marks-rule-changes-that-make-old-snapshots-un.md)). Signs in with `TERRAKIN_ACCESS_TOKEN` or `cloudflared access token`; `TERRAKIN_STAFF_TOKEN` (a maintainer's bearer token) only for a server on this machine, and never over plain http to another. A live world on another `REPLAY_VERSION` passes when every input is accepted, and the new hash is printed. Exits 0 on a match, 1 on a mismatch, a refused input, or a throw, 2 when it couldn't run. The log holds residents' words: it never prints an input, an error message that could quote one (`describeError`), or writes one to disk. `TERRAKIN_SKIP_REPLAY_CHECK=1` makes `deploy.ts` skip it. |
| `persona.ts` | `pnpm persona [visitor\|settled\|stocked\|pet\|staff\|owner] [--name N] [--coins N] [--stacks kind=n,...] [--staff] [--agent Name] [--days N] [--json]` | Makes a resident at a stage on the `pnpm dev:test` server (8797) and prints the JavaScript that signs a tab on :5183 in as them. The stages and steps are `e2e/personas.ts`, shared with the specs ([decision 0147](../docs/knowledge/decisions/0147-test-residents-are-built-through-real-actions-with-a-test-on.md)). Talks only to a server on this machine. |
| `devlog-shot.ts` | `pnpm devlog:shot <name> [--persona settled] [--path /world] [--click <selector>]... [--bare] [--wait ms] [--days N]` | Takes a phone screenshot for a devlog post from the `pnpm dev:test` world: makes a resident at a stage (as `persona.ts` does), opens `--path` signed in as them (`{me}` is their id), presses each `--click`, hides the world's buttons with `--bare`, and saves `packages/client/public/devlog/images/<day>-<name>.jpg`, printing the Markdown line for the post. Talks only to a world on this machine. |
| `docker/` | | The container entrypoint. |

## Rules

- Generators are deterministic: rerunning with no input change writes identical files. Check mode compares content or hashes, never dates.
- Never hand-edit generated output. Change the source and rerun.
- `pnpm townsfolk` against `https://terrakin.org` writes to production. Do a `--dry-run` first, and treat it as the owner's call.
- `pnpm townsfolk -- --handles` is a dry run unless you pass `--send`, which claims each persona's handle (`handle-plan.ts` decides, pure and tested).
- `pnpm townsfolk -- --routines --pets` is a dry run that prints each request it would make, unless you pass `--send`, which sets each persona's routines and adopts its pet (`routine-plan.ts` and `pet-plan.ts` decide, pure and tested). It never adopts a second pet. With `--send` against `https://terrakin.org` it changes the live world: the owner's call.
- `pnpm townsfolk:tips` is a dry run unless you pass `--send`. With `--send` against `https://terrakin.org` it gives real coins: the owner's call. Its choosing logic lives in `packages/server/src/tip-plan.ts`, pure and tested with fixtures, and shared with the server's daily run (`packages/server/src/townsfolk-tips.ts`), which gives the tips on terrakin.org; keep the network and files in `tips.ts`.
- Each persona's `specialties`, the recipes the server's lessons run has it teach (RFC 0024), live in `packages/server/src/lesson-plan.ts`, which `personas.ts` reads like `TIP_NOTES`. Nothing here sends them.
